### 🧪 테스트 케이스 상세 정의 (5가지 필수 시나리오)

다음은 법적 리스크가 감지되었을 때 시스템이 예상대로 작동하는지 검증하기 위한 최소 5가지 핵심 테스트 케이스입니다.

#### Test Case 1: 정상 성공 경로 (Happy Path - Low Risk)
*   **목표:** 정상적인 데이터 입력 시, 예측 로직이 정확하게 '잠재적 손실액'을 계산하고 통과하는지 확인한다.
*   **입력 데이터 (Input Data):** 낮은 수준의 리스크를 가진 일반적인 법규 준수 상황 데이터 (예: 표준 계약 조건).
*   **예상 결과 (Expected Result):** `cost_avoidance` 값이 양수 또는 0으로 계산되어야 하며, 시스템이 정상적으로 성공 응답을 반환해야 한다.
*   **검증 포인트:** API 호출 성공 여부 (HTTP 200 OK) 및 계산된 손실액의 합리성 확인.

#### Test Case 2: Critical Risk 경로 (High Loss Scenario - Failure Path Focus)
*   **목표:** 법적 리스크가 **Critical** 수준으로 감지되었을 때, 시스템이 최대 잠재적 손실액을 정확히 계산하고 가장 높은 경고 레벨을 반환하는지 확인한다.
*   **입력 데이터 (Input Data):** 고위험 계약 또는 규제 위반 가능성이 매우 높은 상황 데이터 (예: 중대한 FTA 위반 징후).
*   **예상 결과 (Expected Result):** `cost_avoidance` 값이 최대치로 계산되어야 하며, 시스템이 명확한 **Critical 경고 메시지**와 함께 해당 손실액을 반환해야 한다.
*   **검증 포인트:** 리스크 레벨(`risk_level`)과 계산된 비용 간의 1:1 매핑 확인 및 Critical 상태에서의 에러 처리 로직 검증.

#### Test Case 3: 데이터 누락/유효성 검사 실패 (Input Validation Failure)
*   **목표:** 필수 입력 데이터가 누락되었을 때, 시스템이 오류를 발생시키고 '잠재적 손실액' 계산을 시도하지 않도록 방어하는지 확인한다.
*   **입력 데이터 (Input Data):** `diagnosis_input`의 필수 필드(예: 계약 금액, 관할 지역 등) 중 하나 이상을 누락하거나 잘못된 형식으로 입력.
*   **예상 결과 (Expected Result):** API 호출 실패 (HTTP 400 Bad Request) 및 명확한 유효성 검사 에러 메시지 반환. 손실액 계산 로직이 실행되지 않아야 한다.
*   **검증 포인트:** JSON Schema 기반의 입력 유효성 검사가 정확히 작동하는지 확인.

#### Test Case 4: 경계값 테스트 (Boundary Condition Testing)
*   **목표:** 잠재적 손실액 계산의 수학적 경계(Zero, 극단적인 값)에서의 안정성을 확인한다.
*   **입력 데이터 (Input Data):** 리스크가 **Normal** 범위의 최소값과 최대값에 해당하는 데이터를 입력하거나, 비용 값이 0이 되는 시나리오를 테스트한다.
*   **예상 결과 (Expected Result):** 경계값에서 계산 오류 없이 안정적인 결과를 반환해야 한다. 특히, 손실액이 0일 때의 시스템 상태가 일관성을 유지하는지 확인한다.
*   **검증 포인트:** 최소/최대 리스크 값에 따른 비용 산출 공식의 정확성 검증.

#### Test Case 5: 외부 데이터 연동 실패 (External Dependency Failure)
*   **목표:** 만약 예측 로직이 외부 데이터 소스(예: 법규 DB, 시장 변동 데이터)에 의존할 경우, 해당 데이터 접근 실패 시 시스템이 안전하게 처리하는지 확인한다.
*   **입력 데이터 (Input Data):** 리스크 계산에 필요한 외부 데이터가 제공되지 않거나 API 호출이 거부되는 환경을 시뮬레이션한다 (Mocking 환경 설정).
*   **예상 결과 (Expected Result):** 시스템은 계산을 중단하고, '데이터 부족' 또는 '외부 정보 접근 실패'와 같은 명확한 오류 메시지를 반환하며, **계산된 손실액 필드는 안전값(Safe Default)으로 처리**되어야 한다.
*   **검증 포인트:** 외부 의존성 실패 시 시스템의 안전 장치(Fail-safe mechanism) 작동 여부 확인.
