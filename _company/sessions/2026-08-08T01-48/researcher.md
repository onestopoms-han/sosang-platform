# 📊 통제 및 실행 로직 매핑 상세 스펙 (Customs Data Mapping Specification)

## 1. 핵심 가치와 관세 데이터의 연결 철학

우리의 목표는 단순한 **'규제 준수 여부(Compliance Status)'** 보고를 넘어, 잠재적 **'손실 회피(Loss Aversion)'**라는 감성적 요소를 정량화하여 **'통제권 확보(Authority Flow)'**로 전환하는 것입니다.

| 심리/비즈니스 개념 | 목표 (Actionable Goal) | 관세 데이터 매핑 영역 (Customs Data Analog) |
| :--- | :--- | :--- |
| **손실 회피 (Loss Aversion)** | 재무적 손실의 예측 및 최소화 | 예상 관세/부가세 변동성, 납기 지연 리스크 |
| **통제권 확보 (Authority Flow)** | 불확실성 감소와 실행 가능성 증대 | 통관 절차 복잡도, HS 코드 분류 정확도, 규제 변경 속도 |
| **행동 가능한 계획 (Actionable Blueprint)** | 데이터 분석을 즉각적인 행동으로 전환 | 특정 품목의 선적/통관 지연 시나리오 및 대체 경로 제시 |

## 2. 핵심 KPI 정의 및 관세 데이터 연계 로직

다음 세 가지 핵심 KPI는 원시 관세 데이터를 가공하여 '감성적 리스크'로 변환하는 필터 역할을 수행해야 합니다.

### 2.1. 통제 점수 (Control Score) 산출 로직
**정의:** 현재 시장/규제 환경에서 사용자가 얼마나 효과적으로 통제권을 행사하고 있는지를 나타내는 지표 (0-100점).

$$
\text{Control Score} = f(\text{Risk Mitigation Efficacy}, \text{Actionability Score}, \text{Compliance Buffer})
$$

*   **Risk Mitigation Efficacy (위험 완화 효율성):** 실제 발생한 손실 대비 예측된 통제 조치 성공률. (예: 예상 관세 변동 $\Delta$ vs. 실제 지불액)
*   **Actionability Score (실행 가능성 점수):** 분석 결과가 실제 행동 계획으로 전환되는 데 걸린 시간 및 난이도. (인지 부하 이론 적용)
*   **Compliance Buffer (준수 완충재):** 현재 확보된 규제 준수 마진. (예: 예상 통관 기간 대비 실제 소요 기간의 여유분).

### 2.2. 실행 가능성 점수 (Actionability Score) 산출 로직
**정의:** 분석 결과가 구체적인 행동 지침(Blueprint)으로 전환되는 효율성을 측정합니다.

*   **로직:** 복잡도 대비 명확성 비율 ($\frac{\text{명확한 실행 단계 수}}{\text{총 데이터 포인트 수}}$).
*   **관세 매핑 예시:** HS 코드 분류 오류 발생 시, 올바른 분류 경로 및 필수 서류 목록을 제시하는 데 필요한 정보의 밀도를 측정합니다.

### 2.3. 위험 완화 효능 (Risk Mitigation Efficacy) 산출 로직
**정의:** 예측된 재무적 손실(Loss)을 얼마나 효과적으로 감소시켰는지에 대한 효율성 지표.

*   **로직:** $\text{Efficacy} = 1 - \frac{|\text{Actual Loss} - \text{Predicted Loss}|}{\text{Predicted Loss}}$ (예측 오류율 기반)
*   **관세 매핑 예시:** 예측된 관세 변동($P_{tax}$)과 실제 지불 관세($A_{tax}$)의 차이를 통해, 시스템이 제공한 경고가 실제로 비용 절감에 기여했는지 측정합니다.

## 3. 데이터 전처리 및 유효성 검사 (Validation Rules)

관세청 데이터를 시스템에 입력하기 전, 다음 규칙을 반드시 적용하여 데이터의 신뢰도를 확보해야 합니다.

### 3.1. 필수 필드 존재 여부 검증
모든 예측 모델은 최소한 다음 핵심 정보가 존재해야 합니다. 누락 시 즉시 **'데이터 불충분(Insufficient Data)'** 상태로 플래그를 지정합니다.

*   **필수 항목:** HS Code (정확성 확인), 원산지 증명 서류 (Certificate of Origin, COO) 유무, 예상 선적/통관 시점, 관련 관세율 기준일.
*   **유효성 검사 규칙:** $\text{HS Code}$는 6단위까지의 일치도를 최소 $95\%$ 이상 요구하며, 오류 발생 시 즉시 재검증을 요구합니다.

### 3.2. 정량적 데이터 일관성 검증 (Consistency Check)
데이터 간의 논리적 모순을 탐지하여 데이터 품질을 확보합니다.

*   **규칙 A (시간 일관성):** 예측된 통관 기간은 실제 관세청 기록상의 평균 통관 소요 기간($\mu$) 대비 $\pm 20\%$ 범위 내에 있어야 합니다. ($\text{Predicted Time} \in [\mu - 0.2\mu, \mu + 0.2\mu]$)
*   **규칙 B (비례성 검증):** 관세율 변동($\Delta\text{Tariff}$)과 예상되는 심리적 불안정성 지표(예: Margin Volatility) 간에 최소한의 상관관계($\rho > 0.5$)가 존재해야 합니다. 만약 변동성이 높으나 관련 데이터가 부재하면 경고를 발생시킵니다.

### 3.3. Edge Case 처리 기준 (Error Handling Protocol)

| Edge Case 시나리오 | 진단/처리 방법 | 권위 흐름 적용 방안 |
| :--- | :--- | :--- |
| **데이터 누락 (Missing Data)** | 해당 지표를 **'불확실성(Uncertainty)'**으로 대체하고, Control Score 계산에서 해당 항목의 가중치를 $0$으로 설정한다. | 예측을 제공하지 않고, **"정보 부족 — 추가 데이터 확보 필요"** 메시지를 사용자에게 명확히 제시하여 실행을 중단시킨다. (인지 부하 최소화) |
| **규제 변경 발생 (Sudden Policy Shift)** | 시스템은 실시간 정책 업데이트 모듈(외부 연동)을 통해 즉시 경고를 발령하고, 기존 예측 모델을 잠정 보류한다. | 즉각적인 '위험' 상태로 전환 후, 사용자에게 **'최신 규제에 따른 재평가 필요'**라는 Actionable Blueprint를 제시한다. |
| **데이터 불일치 (Inconsistency)** | 내부 데이터와 외부 API/관세청 기록 간의 차이가 특정 임계값($\epsilon$)을 초과할 경우, 해당 데이터를 '잠정 보류(Pending Review)' 상태로 표시하고 전문가 검토 대기열에 올린다. | 신뢰도를 저해하는 정보는 절대 예측에 사용하지 않고, **'검토 필요(Requires Review)'** 플래그를 최상단에 표시한다. |
