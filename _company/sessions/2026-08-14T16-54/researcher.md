### 2. 시스템 강건성 및 예외 처리 로직 정의 (Safety Default Values)

시스템은 모든 API 호출과 계산 과정에서 아래의 안전 기본값을 참조하여 **데이터 무결성**과 **사용자 심리 안정감**을 최우선으로 보장해야 합니다.

| 발생 상황 | 적용할 안전 기본값 (Safe Default Value) | 논리 및 근거 | 관련 감성 요소 |
| :--- | :--- | :--- | :--- |
| **입력 데이터 누락/오류** (예: 원자재 가격, 인건비 등) | **$0.0$ 또는 $1.0$ (상황에 따라)** | `2026-8-14/자율 사이클` (시스템 강건성 최우선 확보). 데이터가 없으면 계산을 중단하고 '데이터 누락' 경고를 발생시켜 사용자가 추가 입력을 하도록 유도한다. | 통제권 회복, 불안정성 감소 |
| **예측 모델 실패/불확실성 극대화** (모델 예측값의 신뢰도 저하) | **최소 안전 범위 설정 ($0.5$ 또는 경계값)** | `2026-7-07/Researcher 검증된 지식` (감성적 리스크 관리). 불확실성이 최고조에 달할 때, 시스템은 '위험'을 알리되 '해결책이 없는 상태(0.5)'를 제시하여 사용자에게 **인지 부하**를 줄인다. | 안정감, 명확한 경고 |
| **시스템 연동 오류/API 실패** (외부 데이터 호출 실패) | **안전 기본값: $0.0$ (손실 최소화)** | `2026-8-14/자율 사이클` (안전 기본값). 외부 데이터 연결 실패는 재무적 손실(Risk)을 즉시 발생시키므로, 시스템은 오류를 숨기지 않고 **최소 손실** 상태로 설정하여 사용자가 다음 행동을 취할 수 있도록 한다. | 손실 회피 (Loss Aversion) |
| **경계값 에러 발생 시** (예: Margin Volatility가 비현실적 범위 초과) | **노란색 경고 플래그 활성화 ($\text{Warning Flag}$)** | `2026-8-14/자율 사이클`. 시스템은 오류를 숨기지 않고, 사용자가 즉시 개입할 수 있도록 명확한 시각적 알림(UI)과 함께 구체적인 예외 원인을 제시해야 한다. | 행동 가능한 실행 계획 (Actionable Blueprint) |

### 3. 최종 검증 요약 및 권고 사항

*   **핵심 원칙:** 모든 계산은 **'정보 제공'**이 아닌 **'통제권 확보(Authority Flow)'** 경험을 중심으로 설계되어야 합니다.
*   **강건성 우선:** 시스템의 안정성은 기능 구현보다 최우선이며, 데이터 누락이나 오류 발생 시에는 반드시 `Safe Default Value`를 적용하여 재무적/심리적 손실을 최소화해야 합니다.
*   **시각화 목표:** KPI는 단순한 숫자가 아니라, **'불안정성 감소 $\rightarrow$ 통제권 회복'**의 감성적 흐름(Emotion Flow Manager)을 반영하는 동적인 경험으로 구현되어야 합니다.
