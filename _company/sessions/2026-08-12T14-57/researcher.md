# 📊 무역 정책 위험 지수(TBR Index) 데이터 확보 방안 조사 보고서

**작성일:** 2026년 8월 12일
**목표:** 'Authority Flow Engine'의 핵심 동적 지표인 TBR Index를 실시간으로 연동하기 위한 외부 데이터 수집/처리 방안 비교 분석 및 기술적 타당성 검토.

## 1. 서론: 데이터 확보의 목표 설정

본 보고서의 목표는 법적 불확실성(Risk)을 정량화하고 통제권(Authority Flow)을 시각화하는 서비스의 핵심 동력인 **TBR Index**를 구동하기 위해 필요한 외부 데이터를 가장 효율적이고 신뢰성 있게 확보하는 방법을 제시하는 것입니다. 데이터의 실시간성, 정확성, 접근 용이성을 기준으로 세 가지 주요 방안을 비교 분석합니다.

## 2. 데이터 확보 방안별 상세 분석

### 방식 1: 공식 API 또는 정부 데이터 연동 (API/Government Data)

**개요:** 관세청, 무역 관련 기관 등 정부나 공공기관에서 제공하는 공식 데이터를 직접 API 형태로 요청하거나 연동하는 방식입니다.
**적합성:** 가장 높은 신뢰도와 법적 근거를 제공하며, 장기적인 안정성이 높습니다.
**예상 난이도:** **중상 (Medium-High)**
*   정부 데이터 포털(예: 관세청 데이터)의 API 접근 권한 확보 및 데이터 형식 표준화 작업이 필요합니다. 비공식 API가 존재할 경우, 데이터 정합성 검증에 추가적인 노력이 요구됩니다.
**예상 비용:** **저비용 (Low)**
*   API 사용료가 없거나 매우 저렴하지만, 데이터 포맷 변환 및 연동 로직 개발에 개발 리소스가 투입되어야 합니다.

### 방식 2: 전문 데이터 구독 서비스 이용 (Subscription Service)

**개요:** 무역 통계, 경제 지표 등을 전문적으로 수집하고 정제하여 제공하는 상업용 데이터 제공업체(예: Bloomberg, Refinitiv 또는 특정 무역 데이터 제공사)의 유료 API를 구독하는 방식입니다.
**적합성:** 데이터의 품질과 실시간 업데이트 속도가 보장되어 신뢰성이 매우 높습니다. 특히 전문적인 경제 지표에 유리합니다.
**예상 난이도:** **중 (Medium)**
*   API 키 발급 및 구독료 지불은 용이하나, 서비스별 데이터 포맷 적응 및 비용 관리가 필요합니다.
**예상 비용:** **고비용 (High)**
*   전문 데이터의 특성상 월별 또는 연간 구독료가 발생하며, 이는 MVP 단계에서는 초기 비용 부담으로 작용할 수 있습니다.

### 방식 3: 웹 크롤링 및 자체 파싱 (Web Scraping & Parsing)

**개요:** 공공 포털이나 관련 뉴스 사이트 등에서 필요한 데이터를 직접 스크래핑하여 자체적으로 처리하고 정제하는 방식입니다.
**적합성:** 특정 정보에 대해 가장 유연하게 접근할 수 있으며, 비용 효율성이 높습니다.
**예상 난이도:** **상 (High)**
*   웹사이트 구조 변경에 매우 취약하며, 데이터의 정기적인 유지보수(스크래핑 로직 수정)가 필수적입니다. 법적/윤리적 문제 및 IP 이슈를 반드시 고려해야 합니다.
**예상 비용:** **중~고비용 (Medium-High)**
*   초기 개발 비용은 낮으나, 안정적인 운영을 위한 지속적인 유지보수 인력(또는 로직)이 필요합니다.

## 3. 종합 비교 및 권고 사항

| 구분 | 방식 1: 공식 API 연동 | 방식 2: 전문 구독 서비스 | 방식 3: 웹 크롤링/파싱 |
| :--- | :--- | :--- | :--- |
| **신뢰성** | 높음 (공식 데이터) | 매우 높음 (전문 기관) | 중간 (소스 의존적) |
| **실시간성** | 중간~높음 | 높음 | 낮음 (크롤링 주기 한계) |
| **기술 난이도** | 중상 | 중 | 상 |
| **예상 비용** | 저비용 | 고비용 | 중~고비용 (유지보수 포함) |
| **MVP 적합성** | **최적 (법적 근거 확보 용이)** | 차선책 (초기 비용 부담) | 비추천 (안정성 리스크) |

### 최종 권고 사항: 하이브리드 접근 전략

MVP 단계에서는 **방식 1(공식 API 연동)**을 최우선으로 하여 법적 안정성을 확보하고, 데이터의 정합성을 유지해야 합니다. 초기에는 정부나 공공기관이 제공하는 공개된 무역 관련 데이터를 API 형태로 제공하는지 집중적으로 조사하여 이 방식을 구현합니다.

만약 공식 API를 통해 충분한 실시간 데이터를 얻기 어렵거나, 서비스 차별화를 위해 고도화된 지표가 필요할 경우에 한해 **방식 2(구독)**를 보조 수단으로 고려하며, 방식 3(크롤링)은 시스템의 안정성을 해칠 수 있으므로 최종 단계로 미룰 것을 권고합니다.
