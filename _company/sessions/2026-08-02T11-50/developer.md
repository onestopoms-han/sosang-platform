## 1. PainGauge 핵심 인터랙션 기술 상세 스펙 및 테스트 가이드라인 (디자이너 인계용)

디자이너님께 전달할, **'PainGauge'의 동적 상태 변화 연동 로직**에 대한 기술 명세입니다. 이는 단순한 UI 디자인이 아닌, 시스템의 비즈니스 로직이 시각화되는 핵심 부분이므로, 아래 내용을 기반으로 구현해야 합니다.

### 🎯 1. 목표 및 핵심 가치 (Why)
*   **목표:** 사용자의 리스크 상태(Pain Level) 변화에 따라 재무적 이득(ROI)과 신뢰도(Checkmark)가 **동기화**되어 '선제적 통제권 확보'라는 플랫폼의 핵심 가치를 시각적으로 증명해야 합니다.
*   **핵심 연출:** Yellow $\to$ Gold 상태 전환 시, 단순한 색상 변화를 넘어 **ROI 수치와 체크마크 애니메이션이 동시에 활성화**되는 것을 목표로 합니다.

### ⚙️ 2. 데이터 흐름 및 로직 (How)
| 상태 (State) | PainGauge 시각화 (Visuals) | ROI 연동 방식 (Data Linkage) | 신뢰도 (Trust Widget) | 비고 (Logic Trigger) |
| :--- | :--- | :--- | :--- | :--- |
| **Low Risk** | Green / 낮은 게이지 | 기본값 표시 (Static) | 미활성화 (Disabled) | $\text{Pain} < \text{Threshold}_1$ |
| **Medium Risk** | Yellow (경고) | ROI 변화율을 선형으로 표시 | 미활성화 (Disabled) | $\text{Threshold}_1 \le \text{Pain} < \text{Threshold}_2$ |
| **High Risk** | Orange / Red (위험) | ROI 수치 급변 및 최대 손실액 강조 | 활성화 (Enabled) | $\text{Pain} \ge \text{Threshold}_2$ |
| **Gold State** | Gold (최고 가치) | **ROI 변화가 최대치로 동기화** / 녹색 체크마크 ON | 활성화 (Enabled) | $\text{Pain} \ge \text{Threshold}_3$ |

### ✅ 3. 필수 테스트 케이스 목록 (Test Cases for QA)
디자이너님은 이 테스트 케이스를 기반으로 프론트엔드 구현의 정확성을 검증해주셔야 합니다.

1.  **Transition Test:** PainGauge가 **Yellow 상태($\text{Threshold}_1$ 도달)**에 도달했을 때, ROI 수치가 예상 범위 내에서 변화하는지 확인합니다.
2.  **Gold Trigger Test:** PainGauge가 **Gold 상태($\text{Threshold}_3$ 도달)**로 전환되는 정확한 시점(Pain Level)과 동시에, ROI 값이 최대치로 업데이트되고 녹색 체크마크가 활성화되는지 확인합니다.
3.  **Reversion Test:** Gold 상태에서 다시 Medium Risk로 하락할 때, 모든 요소(ROI, Checkmark)가 **정확히 역순으로 전환**되는지 검증합니다.
4.  **Boundary Test:** 각 $\text{Threshold}$ 지점($\text{Threshold}_1, \text{Threshold}_2, \text{Threshold}_3$)에서 UI/데이터 연동이 명확하게 구분되는지 확인합니다.

### 📜 4. 코딩 표준 가이드라인 (Coda-ri의 요구사항)
*   **상태 관리:** 모든 시각적 변화는 중앙 상태(Global State)에 의해 결정되어야 하며, PainGauge 컴포넌트는 오직 해당 상태를 **렌더링**하는 역할만 수행해야 합니다.
*   **데이터 동기화:** ROI 데이터와 UI 요소의 업데이트는 비동기적으로 이루어지지 않고, **동일한 시점(Synchronous)**에 발생하도록 로직을 설계합니다.
*   **에러 처리:** API 호출 실패 또는 데이터 누락 시, 게이지는 기본 상태로 유지하며 명확한 에러 메시지(`Failure Scenario` 가이드라인 준수)를 표시해야 합니다.
