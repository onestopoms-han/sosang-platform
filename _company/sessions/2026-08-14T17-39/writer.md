# 📄 기술 명세서: Authority Flow Rate 위젯 API 계약 (v2.0)

## 1. 개요 (Overview)

본 문서는 'Authority Flow Rate' 위젯이 백엔드 시스템과 프론트엔드 간에 안전하고 예측 가능한 데이터 교환을 보장하기 위해 정의한 최종 API 계약(Contract)을 명시합니다. 이 명세서는 엔지니어링 팀과 비개발 직군 모두가 위젯의 목적, 호출 방식, 성공 시 예상되는 데이터 구조, 그리고 모든 예외 및 경계 조건에 대한 처리 가이드라인을 이해할 수 있도록 구조화되었습니다.

**핵심 목표:** 시스템 강건성(Robustness) 확보 및 사용자에게 '통제권 회복' 경험 제공.

## 2. 시스템 목적 (Purpose)

`Authority Flow Rate` API는 사용자의 현재 상태(예: 권한, 데이터 임계값)가 다음 단계로 전환되기 위해 필요한 조건을 측정하고 보고하는 역할을 수행합니다. 이는 단순 정보 제공을 넘어, 사용자가 자신의 시스템 통제권을 명확히 인지하고 다음 행동을 취할 수 있도록 돕는 **경험적 가치**를 전달하는 데 중점을 둡니다.

## 3. API 호출 정의 (Invocation)

모든 API 호출은 안전 기본값(Safe Default Value) 원칙에 따라 설계되며, 시스템 오류 발생 시에도 클라이언트가 무너지지 않고 안정적으로 다음 상태로 전환할 수 있도록 설계되었습니다.

| 항목 | 세부 내용 |
| :--- | :--- |
| **엔드포인트** | (구체적인 엔드포인트는 백엔드 명세에 따름) |
| **요청 방식** | GET / POST (상태 조회 또는 상태 업데이트에 따라 결정) |
| **인증** | 필수 (사용자 세션 및 권한 확인) |
| **핵심 원칙** | 모든 응답은 `Safe Default Value`를 포함해야 함. |

## 4. 성공 케이스 응답 스키마 (Success Case Response Schema)

요청이 성공적으로 처리되었을 때 반환되는 데이터 구조는 다음과 같습니다.

### A. 성공 상태 (`200 OK`, `STATUS_OK`)
데이터가 정상적으로 조회 및 반환된 경우.
*   **응답 본문:** 요청된 상태 값과 관련 메타데이터를 포함한 JSON 객체. (예: `{ "status": "OK", "flowRate": 75, "details": "..." }`)

### B. 임계값 미도달 상태 (`200 OK`, `WARN_THRESHOLD_LOW`)
현재 상태가 다음 단계로 전환하기 위한 최소 기준을 충족하지 못한 경우. 이는 사용자에게 추가 정보 제공 및 행동 유도를 위한 신호입니다.
*   **응답 본문:** 시스템이 대기 상태임을 명확히 알리는 메시지와 함께 안전 기본값을 반환합니다. (예: `{"status": "WAITING", "message": "다음 단계를 위해 더 많은 데이터가 필요합니다."}`)

## 5. 실패 및 경계 조건 처리 가이드라인 (Failure & Boundary Handling)

시스템 오류, 권한 문제, 데이터 누락 등 예외 상황 발생 시, 시스템은 예측 불가능한 상태로 전환되는 것을 방지하고 사용자에게 명확한 조치를 유도하기 위해 사전에 정의된 에러 코드와 안전 기본값을 반환해야 합니다.

| HTTP Status Code | 내부 에러 코드 | 설명 (기술적 의미) | Safe Default Value (클라이언트 측 적용 값) | 처리 지침 (개발팀/비개발팀) |
| :--- | :--- | :--- | :--- | :--- |
| `404 Not Found` | `ERR_DATA_MISSING` | 요청된 상태 또는 핵심 데이터가 시스템 내에 존재하지 않음. | `{"status": "INSUFFICIENT", "message": "데이터를 불러올 수 없습니다."}` | **[엔지니어링]**: 데이터베이스 조회 실패 시, 404 응답과 함께 명시적인 에러 코드를 반환해야 함. |
| `403 Forbidden` | `ERR_AUTH_FAIL` | 요청한 상태에 접근할 권한이 사용자 세션 또는 역할에 의해 제한됨. | `{"status": "RESTRICTED", "message": "접근 권한이 제한되어 있습니다."}` | **[비개발]**: 권한 문제는 데이터의 부재가 아닌 접근 제한 문제임을 명확히 인지하고, 권한 기반 필터링 로직을 검증해야 함. |
| `500 Internal Server Error` | `ERR_SYSTEM_FAIL` | 서버 내부에서 예상치 못한 오류가 발생하여 요청 처리가 중단됨. | (시스템 자체 에러 메시지) | **[엔지니어링]**: 모든 예외 경로에 대해 중앙 집중식 로깅 시스템을 통해 즉시 알림을 생성하고, 사용자에게는 일반적인 오류 페이지를 제공해야 함. |

## 6. 핵심 원칙 요약 (Core Principle Summary)

1.  **안전 기본값 우선:** 어떠한 상황에서도 시스템은 정의된 `Safe Default Value`를 반환하여 클라이언트의 안정성을 보장합니다.
2.  **경험적 가치 전달:** 상태 변화(WARN\_THRESHOLD\_LOW)는 단순 오류가 아닌, 사용자에게 다음 행동을 유도하는 '통제권 회복' 경험으로 해석되어야 합니다.
3.  **데이터 기반 명확성:** 모든 실패는 `ERR_DATA_MISSING` 또는 `ERR_AUTH_FAIL`과 같이 구체적인 내부 코드로 분류하여 추적 가능성을 높입니다.
