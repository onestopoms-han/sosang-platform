# 📋 작업 브리프

**원 명령:** 1. 데이터 베이스 및 RAG 매칭 처리 (백엔드 필수)
방대한 레퍼런스 데이터: WCO 관세율표 전체 데이터, 국내외 품목분류 판례(수만 건), 관세청 HS 코드 설명 고시, 유사 규격 평균 단가 데이터 등은 GB(기가바이트) 단위의 데이터베이스에 저장되어 있습니다.
서버 처리: 브라우저(프론트엔드)에서는 이 거대한 데이터베이스를 직접 들고 다닐 수 없으므로, 백엔드에서 벡터 데이터베이스 검색(Vector DB Search) 및 SQL 조인(Join) 연동을 통해 비교 분석을 수행한 뒤 결과물만 프론트엔드로 전달하게 됩니다.
2. 브라우저 성능 한계 극복
브라우저 메모리 내에서 수백만 줄의 수입 신고 행을 직접 정렬하고 계산하려고 하면 **화면이 멈추거나 튕기는 현상(Crash)**이 발생합니다.
백엔드(FastAPI)와 Pandas, PostgreSQL DBMS 같은 고성능 라이브러리 및 하드웨어를 활용해 멀티스레드로 빠르게 계산 처리를 하고 정제된 JSON 통계 정보만 화면에 내려주는 것이 올바른 구조입니다.

## 요약
대용량 관세 데이터 처리 및 비교 분석을 위한 시스템의 핵심 백엔드 아키텍처 설계가 필요합니다. 브라우저 성능 한계를 극복하고 복잡한 규제 데이터를 효율적으로 처리할 수 있는 기술 스택과 로직 흐름 정의가 목표입니다.

## 분배
- **💻 코다리**: 사용자가 제시한 요구사항(GB 단위 대용량 데이터, Vector DB Search + SQL Join 연동)을 기반으로 백엔드 시스템 아키텍처를 설계하십시오. 구체적으로 FastAPI 프레임워크를 활용하여 다음과 같은 기술 구현 계획과 사양서를 작성해야 합니다:

1. **API 명세 정의**: 핵심 기능(예: HS 코드 비교 및 규제 충돌 분석)을 수행하는 엔드포인트(`/api/v1/process_comparison`)의 요청(Request Body) 및 응답(JSON Response) 스키마를 완벽하게 설계합니다.
2. **데이터 파이프라인 로직**: PostgreSQL과 외부 Vector DB를 연결하여 데이터를 검색하고 조인하는 논리적 흐름을 정의하십시오. (예: `Input_Item` $\rightarrow$ `VectorDB Search` $\rightarrow$ `PostgreSQL Join & Filter`)
3. **고성능 처리 모듈 설계**: 대용량 데이터 계산(수입 신고 행 정렬/계산) 시 메모리 과부하를 방지하기 위한 Pandas와 멀티스레딩 로직을 포함한 최적화된 백엔드 처리 흐름을 상세히 명시하고, 이 과정에서 발생할 수 있는 예외 처리 및 성능 병목 지점(Bottleneck)에 대한 해결책을 제시하십시오.
