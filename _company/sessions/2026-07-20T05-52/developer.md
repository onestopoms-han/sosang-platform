### Proof Widget 기술 명세서 초안 (V1.0)

#### 1. 위젯 목표 및 컨셉
**목표:** 사용자가 제품의 '소장 가능한 유산(Heirloom)' 가치를 직관적으로 이해하고 신뢰하도록 한다.
**컨셉:** '유산 인증서' 스타일 (Warm Luxury), 데이터 기반의 권위적 증명.
**핵심 메시지:** "단순 효능이 아닌, 시간과 시스템이 빚어낸 독점적 가치."

#### 2. 데이터 요구사항 (Backend API Contract)
Proof Widget에 필요한 데이터는 백엔드에서 안전하게 제공되어야 하며, 프론트엔드는 이 데이터를 기반으로 시각화만 담당해야 합니다.

**API 엔드포인트 제안:** `/api/v1/proof-metrics` (또는 `DiagnosisOutputSchema`의 확장된 필드로 통합)

| 필드명 | 데이터 타입 | 설명 | 요구되는 근거 |
| :--- | :--- | :--- | :--- |
| `provenance_mark` | String | 블록체인 기반 Provenance Mark의 고유 ID 또는 인증 토큰. (소장 가능 증명) | 🎯 제품 포지셔닝 |
| `system_complexity_score` | Number | **SCS (System Complexity Score)** 지표 값. 생산 시스템의 독점적 복잡성을 정량화한 점수. | 🎯 핵심 지표 |
| `human_potential_value` | Number | **HPV (Human Potential Value)** 지표 값. 사용자에게 제공되는 잠재적 가치 또는 시간 절약 효과를 정량화한 지표. | 🎯 핵심 지표 |
| `value_proposition_summary` | String | 해당 점수들을 바탕으로 도출된, 사용자에게 전달할 핵심적인 '가치 명제' (예: "SCS 95점 달성: 최고 수준의 독점 생산 시스템을 증명합니다.") | 🎨 스토리텔링 지원 |
| `certification_status` | Enum | 인증 상태 (예: `Verified`, `Pending`, `Heirloom`) | ⚙️ 유효성 검증 |

#### 3. 시각화 요구사항 (Frontend/UI Specification)
데이터는 'Warm Luxury' 톤앤매너를 해치지 않으면서도 권위를 부여해야 합니다.

1.  **레이아웃:** 카드 또는 패널 형태로 구성하며, 충분한 여백(Whitespace)을 활용하여 고급스러움을 극대화한다.
2.  **핵심 지표 시각화 (SCS & HPV):**
    *   두 수치를 중앙에 배치하고, 그 주변에 **'인증 마크' 형태의 그래픽 요소**를 삽입한다. (예: 금속성 인증 마크 또는 각인된 서명 느낌)
    *   점수(Score) 자체보다 해당 점수가 의미하는 바(Value Proposition Summary)가 더 크게 보이도록 구성한다.
3.  **Provenance Mark 시각화:** 블록체인 기반의 Provenance Mark는 고유한 디지털 인증서 형태로 표시하며, 클릭 시 원장(Ledger)으로 연결될 수 있는 인터랙션을 제공한다.
4.  **상태 변화 (State Transition):** `certification_status`에 따라 색상 테마를 변경한다. (`Verified`일 경우 Dusty Gold 톤 강조).

#### 4. 기술적 검증 및 통합 방안
*   **백엔드 검증:** API 응답 시, 모든 필드가 필수이며, `SCS`와 `HPV` 값이 비즈니스 로직 내에서 **최소/최대 범위(Range)**를 벗어나지 않는지 서버 레벨에서 재검증해야 한다. (`Self-RAG` 프로토콜에 따라 데이터 무결성 최우선).
*   **프론트엔드 검증:** `value_proposition_summary`가 API로부터 정상적으로 수신되었는지 확인하고, 데이터 누락 시 에러 상태(`Pending`)를 명확히 표시한다.
