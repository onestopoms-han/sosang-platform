# 📋 MVP 데이터 포인트 최종 검증 체크리스트 (개발자용)

본 체크리스트는 MVP 내 모든 데이터 입력 및 처리 로직이 **재무적 손실 관리(Loss Aversion)**와 **행동 가능한 실행 계획(Actionable Blueprint)**의 원칙에 따라 유효성을 검증하도록 설계되었습니다.

## 1. 법적 근거 및 규제 데이터 (Legal & Regulatory Data)

모든 법적/규제 관련 데이터는 시스템의 핵심 신뢰성(Trustworthiness)을 보장하는 가장 중요한 요소입니다.

| 데이터 항목 | 필수 검증 사항 | 요구되는 출처 | 필수 입력값 범위 (Range) | 최신 규정 기준 연동 |
| :--- | :--- | :--- | :--- | :--- |
| **법적 근거 ID** (예: 관세율, 세금 코드) | 데이터의 유효성 및 무결성 검증 | 정부 공식 데이터베이스 또는 공인된 법률 API | [최소값] $\le$ 값 $\le$ [최대값] | 실시간 규정 업데이트 모듈 연동 확인 |
| **규제 변동일** (Regulation Change Date) | 데이터의 시점 적절성 검증 | 공식 발표 기록 또는 데이터 갱신 로그 | 과거 $N$개월 이내 변경 여부 플래그 | 규제 시스템과의 동기화 주기 확인 |
| **지역별 적용 범위** (Jurisdiction Scope) | 지리적/법적 경계의 정확성 | 국제 표준 지도 데이터 및 관세 구역 정의 | 0 또는 특정 지역 코드 매핑 | 각 관할권별 법규 차이 반영 여부 |

## 2. 재무 및 성과 데이터 (Financial & Performance Data)

재무 지표는 사용자의 '불안정성(Anxiety)'을 관리하고 '통제권 회복'을 지원하는 핵심 감성적 요소입니다.

| 데이터 항목 | 필수 검증 사항 | 요구되는 출처 | 필수 입력값 범위 (Range) | 최신 기준 적용 로직 |
| :--- | :--- | :--- | :--- | :--- |
| **예상 이익 변동성** (Margin Volatility) | 수익 예측의 현실성 및 위험 측정 | 과거 데이터 트렌드 분석, 시장 지표 연동 | $\text{Min} \le \text{변동성} \le \text{Max}$ (역사적 범위 기반) | Cost of Delay (CoD) 지표와의 상관관계 검증 |
| **손실 회피 비용** (Risk Aversion Cost) | 사용자의 심리적 손실 인지 반영 여부 | 행동경제학 모델 매핑 및 사용자 입력 기반 산출 | $\text{Cost} > 0$ 이고, 측정 단위의 일관성 | 불안정성 지표($\text{Anxiety}$)와 UI/UX 색상 변화 로직 연동 |
| **실행 가능 예측** (Actionable Prediction) | 제시된 실행 계획이 현실적으로 달성 가능한지 검증 | Actionable Blueprint 모듈의 결과 | $\text{Success Rate} \in [0\%, 100\%]$ | KPI 목표 대비 실제 실행률 차이 분석 |

## 3. 시스템 및 데이터 출처 무결성 (System & Data Integrity)

시스템 강건성(Robustness) 확보를 위해 데이터 공급망의 신뢰도를 검증합니다.

| 데이터 항목 | 필수 검증 사항 | 요구되는 출처 | 필수 입력값 범위 (Range) | 최신 기준 적용 로직 |
| :--- | :--- | :--- | :--- | :--- |
| **데이터 출처 ID** (Data Source ID) | 모든 데이터 포인트의 원본 추적성 확보 | DB 레코드 ID 또는 API 호출 로그 | 고유 식별자(UUID/ID) 형식 준수 | 데이터 흐름 감사 로그 기록 |
| **최신 규정 기준 적용일** (Latest Standard Date Applied) | 사용된 기준이 최신인지 확인 | 시스템 내부 규정 관리 모듈 | 현재 날짜 $\le$ 적용일 | 시스템 업데이트 시 자동 검증 트리거 설정 |
| **예외 처리 결과 코드** (Error Handling Code) | 오류 발생 시 안전 기본값(Safe Default Value) 준수 여부 | 코다리 로직의 예외 처리 로그 | 정의된 에러 코드 집합 내에 포함되는지 확인 | 모든 API 응답에 대한 안전 장치 검증 |
