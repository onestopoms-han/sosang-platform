## 1. 시스템 위험 지표 및 대시보드 요구사항 (Risk Indicators & Dashboard Requirements)

시스템은 실시간으로 감지된 법적/규제 리스크를 정량화하고, 이를 시각적으로 명확히 표시해야 한다. 이는 사용자에게 '위기 감지'가 아닌 '통제권 회복' 경험을 제공하는 핵심 UX 요소이다.

### 1.1. 위험 레벨 (Risk Level) 정의
시스템은 법적 리스크를 다음의 세 가지 등급으로 분류하고, 각 단계에 따라 대시보드의 색상 및 애니메이션을 동적으로 변경해야 한다.

| 위험 레벨 | 정의 (기술적 의미) | UI/UX 표현 (색상 조합) | 시스템 상태 |
| :--- | :--- | :--- | :--- |
| **Critical (심각)** | 즉각적인 법적 제재 또는 운영 중단 가능성이 있는 상황. (예: 수출입 금지, 관세율 대폭 상향 등) | **Deep Forest Green** + Rich Gold (경고 및 긴급 조치 필요) | 시스템 비활성화/강력 경고 모드 |
| **Warning (주의)** | 잠재적 리스크가 존재하며 즉각적인 대응이 필요한 상황. (예: 변경된 FTA 적용 가능성, 데이터 이동 규정 준수 미흡) | **Amber** + Gold (주의 및 검토 필요) | 실행 계획(Actionable Blueprint) 모듈 활성화 |
| **Normal (정상)** | 현재 시스템 운영 범위 내에서 법적 리스크가 관리되고 있는 상태. | **Green** (안정성 확보) | 표준 운영 모드 |

### 1.2. 필요한 근거 데이터 유형 (Required Evidence Data Types)
위험 레벨을 산출하기 위해 시스템이 필수적으로 수집하고 연동해야 할 데이터는 다음과 같다.

*   **법규 변경 로그 (Regulatory Change Log):** FTA, 관세율, 원산지 규정(ROO), 데이터 국경 이동 관련 법령의 최신 개정 사항 및 시행일을 기록한 데이터 스트림.
*   **실시간 트랜잭션 데이터 (Real-time Transaction Data):** 특정 거래(수출입 건, 데이터 전송량 등)가 발생했을 때, 해당 데이터가 적용되는 관할 지역과 관련 법규를 매핑하는 데이터.
*   **데이터 이동 메타데이터 (Data Migration Metadata):** 국경을 넘는 데이터의 종류(민감 정보 여부), 이동 경로, 목적지 국가 및 관련 개인정보 보호 규정(GDPR 등) 준수 여부를 기록한 데이터.
*   **내부 리스크 매트릭스 (Internal Risk Matrix):** 시스템이 자체적으로 정의한 위험 요소와 실제 발생한 트랜잭션 간의 연관성을 점수화한 내부 지표.

## 2. 시스템 제시 법적 대응 가이드라인 모듈 (Legal Response Guideline Module)

위험 레벨이 활성화될 경우, 시스템은 단순 경고를 넘어 사용자가 즉시 취할 수 있는 구체적인 '실행 가능한 통제권 회복 경로(Actionable Blueprint)'를 제공해야 한다. 이 섹션은 법률 전문가의 최종 검토가 필요함을 명시한다.

### 2.1. 위험 레벨별 자동 제시 가이드라인
| 위험 레벨 | 시스템이 제시해야 할 핵심 대응 지침 (System Suggestion) | 법적 근거 요청 데이터 유형 |
| :--- | :--- | :--- |
| **Critical** | **[긴급 조치]:** 즉시 해당 거래/데이터 이동을 중단하고, 관세 당국 또는 관련 규제 기관에 보고할 것을 권고한다. **(Legal Stop)** | 법규 변경 로그 (최신), 트랜잭션 데이터 |
| **Warning** | **[검토 필요]:** 해당 거래의 원산지 증명서 및 데이터 국경 이동 승인 절차를 재확인하고, 관련 당국에 제출할 증빙 자료 목록을 제시한다. **(Compliance Check)** | 데이터 이동 메타데이터, 법규 변경 로그 |
| **Normal** | **[모니터링]:** 현재 상태 유지를 권고하며, 다음 분기/월간 시스템 모니터링 주기와 예상되는 잠재적 변화 시나리오를 제공한다. **(Proactive Monitoring)** | 내부 리스크 매트릭스, 트렌드 데이터 |

### 2.2. 법적 대응 가이드라인 구조 (Template for Guidance)
시스템은 다음의 구조를 통해 사용자에게 대응 방안을 제시해야 한다.

1.  **리스크 요약:** 현재 시스템이 감지한 핵심 리스크(예: "특정 데이터는 EU GDPR 규제 준수 여부가 불확실함").
2.  **필요 근거 자료 목록:** 해당 리스크를 해소하기 위해 사용자가 준비해야 할 구체적인 법적/행정적 증빙 자료 목록 (예: 원산지 증명서 사본, 데이터 처리 동의서).
3.  **권고된 실행 단계 (Actionable Blueprint):**
    *   **Step 1 (진단):** 현재 상황에 대한 최종 확인 및 관련 법규 인용.
    *   **Step 2 (수집):** 필요한 증빙 자료를 수집하는 구체적인 절차 안내.
    *   **Step 3 (대응):** 시스템 내에서 실행 가능한 다음 단계(예: '데이터 이동 승인 요청 양식' 자동 생성) 제시.
