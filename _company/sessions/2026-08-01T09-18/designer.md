# 🖼️ Landing Page Mock-up 상세 명세서 (RRS Dynamic Flow)

## 1. 디자인 시스템 정의 (Visual System Definition)

### 1.1. 핵심 컬러 팔레트 (Core Color Palette)
| 역할 | 색상 이름 | HEX 코드 | 사용 맥락 | 근거 |
| :--- | :--- | :--- | :--- | :--- |
| **불안/위험** | Red Zone | `#D93E3E` | 불안정성, 위험 경고 (Red) | 데이터 기반 권위 |
| **경고/변화** | Yellow Zone | `#FFC107` | 주의, 변화 과정 (Yellow) | 데이터 기반 권위 |
| **통제/확보** | Gold Zone | `#FFD700` | 성공 상태, 통제권 확보 (Gold) | 데이터 기반 권위 |
| **안정/성장** | Green Zone | `#28A745` | 안정 상태, 성과 달성 (Green) | 데이터 기반 권위 |
| **기반 배경** | Deep Forest Green | `#1E403D` | 주 배경 색상, 신뢰감 부여 | 데이터 기반 권위 |

### 1.2. 타이포그래피 시스템 (Typography System)
*   **헤드라인 (H1/H2):** 산세리프 계열 (예: Pretendard/Inter), Bold, 크기 차등 적용하여 시각적 계층 구조 확보.
*   **본문 (Body):** 가독성을 최우선으로 하며, 충분한 행간(Line Height)을 확보하여 불안감을 완화하고 정보 수용도를 높임.

### 1.3. 핵심 인터랙션 스펙: RRS 게이지 컴포넌트
이 컴포넌트는 랜딩 페이지의 중앙 또는 Hero 섹션에 배치되어 사용자의 현재 상태를 실시간으로 시각화합니다.

*   **요소:** 원형 진행 게이지 (Radial Progress Gauge) 형태.
*   **색상 블렌딩 로직:** RRS 점수에 따라 배경 및 내부 라인의 색상이 동적으로 변하며 부드럽게 전환되어야 합니다.
    *   **Red Zone (0% ~ 30%):** 배경/경계선은 `Red Zone` (`#D93E3E`), 핵심 지표는 어두운 회색으로 표시. **(불안 극대화)**
    *   **Yellow Zone (31% ~ 70%):** 색상이 점진적으로 `Yellow Zone` (`#FFC107`)으로 블렌딩되며, 애니메이션은 부드러운 그라데이션 전환(`ease-in-out`)을 사용. **(변화 과정 인지)**
    *   **Gold Zone (71% ~ 100%):** 배경/경계선은 `Gold Zone` (`#FFD700`)으로 고정되며, 핵심 지표는 밝은 골드로 강조됨. **(통제권 확보)**
*   **애니메이션 스펙:** 색상 전환 시, 단순한 색상 변경이 아닌, **미세한 진동 및 상승/하강 애니메이션(Subtle Pulse/Shift)**을 적용하여 데이터 변화의 '역동성'을 강조합니다.

## 2. 섹션별 UI 레이아웃 상세 설계 (Wireframe Specification)

**레이아웃 방향:** 세로 스크롤 기반의 단일 페이지 흐름. 각 섹션은 명확한 시각적 분리와 감정적 전환을 유도해야 합니다.

### Section 1: Hero Section (최상단, 시선 집중)
**목표:** 가장 강력한 불안감을 제시하고 즉각적인 행동(진단)으로 연결한다.

*   **배경:** `Deep Forest Green` (`#1E403D`) 계열의 어두운 톤을 사용하여 심각성과 전문성을 동시에 부여합니다.
*   **레이아웃:** 중앙 집중형 (Center-Aligned).
    *   **좌측/우측 배치:** Hero 섹션 좌측에는 RRS 게이지 컴포넌트(최대치 기준)를 시각적으로 배치하여 '데이터 기반'이라는 인식을 즉시 심어줍니다.
    *   **헤드라인 (H1):** "당신의 비즈니스, 데이터에 기반한 '불안' 속에 갇혀 있진 않습니까?" (`#FFFFFF` 또는 밝은 골드) - 가장 크고 굵게 배치.
    *   **CTA 버튼:** **"내 비즈니스의 불안정성 즉시 진단하기"** (Gold Zone 배경, 대비되는 텍스트). 클릭 시 RRS 진단 페이지로 이동.

### Section 2: Pain Point Diagnosis Section (문제 인식 유도)
**목표:** 추상적인 어려움을 구체적인 '위험'으로 전환하여 공감대를 형성한다.

*   **배경:** `Deep Forest Green` 계열 유지.
*   **레이아웃:** 3단 분할 레이아웃 (Visual Hierarchy 강조).
    *   **헤드라인 (H2):** "보이지 않는 위험, 당신의 성장을 멈추게 하는 진짜 원인은 무엇인가요?"
    *   **본문 배치:** 본문의 각 문장(매일 예측 불가능한 시장 변화...)은 별도의 **아이콘과 함께** 시각적으로 분리하여 제시합니다. (예: 불안정성 $\rightarrow$ 아이콘, 리스크 축적 $\rightarrow$ 아이콘)
    *   **CTA 버튼:** **"나의 리스크 점수(RRS)로 현재 상태 진단받기"** (Yellow Zone 배경 또는 Gold 테두리).

### Section 3: RRS Change Explanation Section (해결책 제시 및 메커니즘 공개)
**목표:** 서비스의 핵심 가치('RRS'와 '통제권 확보')를 설명하고 신뢰도를 구축한다.

*   **배경:** 약간 밝은 톤(`Deep Forest Green`에서 명도 상향 또는 연한 회색 계열)을 사용하여 정보 전달의 명확성을 높입니다.
*   **레이아웃:** 수평적 흐름 (Flow-based).
    *   **헤드라인 (H2):** "데이터가 당신에게 '통제감(Gold)'을 되찾아주는 시스템"
    *   **핵심 메커니즘 시각화:** Red $\to$ Yellow $\to$ Gold의 **변화 과정을 시퀀스 애니메이션**으로 구현합니다. 세 가지 상태를 나란히 배치하고, 각 상태 간의 화살표는 부드러운 흐름(Flow)을 나타내야 합니다.
    *   **본문:** RRS가 어떻게 통제권을 제공하는지에 대한 설명을 명확한 블록 형태로 구성하며, **핵심 키워드('RRS', '통제권')는 Gold로 강조**합니다.
    *   **CTA 버튼:** **"RRS 기반의 맞춤형 성장 로드맵 확인하기"** (Gold Zone 배경).

### Section 4: Blueprint Introduction Section (실행 계획 제시)
**목표:** 진단에서 실행으로 이어지는 구체적인 행동 방안(Blueprint)의 존재를 강조한다.

*   **배경:** 다시 안정적인 `Deep Forest Green`으로 복귀하여 결론과 행동을 명확히 합니다.
*   **레이아웃:** 2분할 레이아웃 (좌측: 실행 계획, 우측: 신뢰 확보).
    *   **헤드라인 (H2):** "당신의 불안을 해소하고 성장을 가속화하는 구체적 실행 방안"
    *   **좌측 (Blueprint Focus):** 'Blueprint'에 대한 간결한 설명 및 다음 단계의 예시(예: 3단계 로드맵)를 시각적으로 제시.
    *   **우측 (Trust Focus):** 기술적 근거(RAG, 법률 검토 고지 등)와 연결하여 **신뢰성**을 강조하는 작은 아이콘과 함께 배치합니다.
    *   **최종 CTA:** 가장 중요한 실행 버튼을 다시 한번 배치합니다.

## 3. 개발팀 인계용 최종 명세 (Developer Handover Specification)

**요약:** 이 Mock-up은 정적인 이미지가 아닌, **상태 변화에 따른 동적 UI 컴포넌트(Dynamic UI Component)**로 구현되어야 합니다.

1.  **State Management:** RRS 점수(0~100)를 상태 변수로 관리하며, 이 값이 변경될 때마다 색상 및 애니메이션 로직이 트리거되어야 합니다.
2.  **RRS Gauge Implementation:** `progress` 값에 따라 CSS `background-color`와 `box-shadow`의 색상이 순차적으로 블렌딩되도록 구현합니다. (Red $\to$ Yellow $\to$ Gold)
3.  **Animation Specification:** 모든 전환 효과는 **600ms 이내**로 부드럽게 처리되어야 하며, 데이터가 '감'이 아닌 '과학적 근거'에 기반함을 시각적으로 증명해야 합니다. (Golden Ratio 애니메이션 스펙 준수)
4.  **Responsiveness:** 모바일 환경에서는 모든 텍스트와 CTA는 충분한 터치 영역을 확보하며, 게이지 컴포넌트는 화면 폭에 맞춰 유연하게 반응하도록 설계합니다.
