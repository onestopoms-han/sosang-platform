# 🛡️ End-to-End 통합 테스트 계획서: 시스템 안정성 및 안전 기본값 검증 (V1.0)

**🎯 목표:** 시스템 실패 시 **안전 기본값(Safe Default Value)**이 정상적으로 작동하는지, 모든 외부 API 연동 지점과 리스크 프로세서 서비스 계층이 예외 상황에서도 무결성을 유지하는지 E2E 관점에서 검증한다.

**⚙️ 핵심 원칙 (Coda-ri 적용):**
1.  **실패 시나리오 우선:** 성공 경로 테스트보다 **예외 및 실패 경로(Failure Path)** 테스트에 70%의 리소스를 할당한다.
2.  **경계 조건 집중:** 입력 데이터(`DiagnosisInputSchema`)의 경계값, 비정상 값, 누락 상태를 의도적으로 주입하여 시스템 반응을 검증한다.
3.  **Safe Default Value 검증:** 모든 실패 지점에서 시스템이 명시된 안전 기본값으로 전환되는지(Failover)를 측정한다.

## 1단계: 입력 및 진단 계층 테스트 (Input & Diagnosis Layer Testing)

**목표:** 입력 데이터의 유효성 검사(`Validation`)와 초기 진단 로직의 경계 조건을 확인한다.

| ID | 테스트 시나리오 | 입력 데이터 조건 | 기대 결과 (Success Path) | 기대 결과 (Failure/Failover Path) | 우선순위 |
| :---: | :--- | :--- | :--- | :--- | :---: |
| **T1.1** | 필수 필드 누락 테스트 | `DiagnosisInputSchema`에서 핵심 필드(예: HS Code, Quantity)를 완전히 누락하거나 빈 문자열(`""`)로 입력 | 유효성 검사 실패 및 적절한 에러 메시지 반환 | 시스템이 에러 상태를 안전하게 기록하고, 다음 단계 호출을 **차단**함 (Safe Stop). | **P1 (Critical)** |
| **T1.2** | 경계값 초과 테스트 | 수량(Quantity) 또는 가격(`Value`) 필드에 최대 허용치($Max$)보다 1 증가한 값 입력 | `SafeExecutor`가 작동하여, 시스템이 오류를 반환하고 안전 기본값으로 전환함 (Failover). |
| **T1.3** | 비정상 데이터 주입 | HS Code 또는 기타 규제 관련 필드에 존재하지 않는 문자열(`"INVALID_CODE"`)을 입력 | 리스크 프로세서 서비스 계층이 해당 데이터를 거부하고, 안전 기본값(예: 'Unknown Risk')으로 설정함. |

## 2단계: 핵심 로직 및 액션 플랜 서비스 테스트 (Core Logic & Action Plan Service Testing)

**목표:** `action_plan_service`의 복잡한 조건부 로직과 상태 전이(`State Transition`)가 실패 시 안전하게 처리되는지 검증한다.

| ID | 테스트 시나리오 | 입력 데이터 조건 | 기대 결과 (Success Path) | 기대 결과 (Failure/Failover Path) | 우선순위 |
| :---: | :--- | :--- | :--- | :--- | :---: |
| **T2.1** | 실패 경로 강제 실행 | T1단계에서 실패를 유발한 입력 데이터(예: T1.1)를 `action_plan_service`로 직접 전달 | 서비스가 예외를 발생시키고, 오류 로그를 기록하며, 시스템 상태는 **'Error State'**로 명확히 전환됨. |
| **T2.2** | Safe Default 활성화 검증 | T2.1에서 발생한 실패 후, 시스템이 자동으로 `SafeExecutor` 패턴을 통해 **Predefined Fallback Plan**으로 전환하는지 확인. | 시스템이 재시도(Retry)하거나 안전 모드(Safe Mode)로 진입하며, 사용자에게 오류 대신 가이드라인 제공. |
| **T2.3** | 상태 비일관성 테스트 | 특정 단계(`StoryFlowSchema`의 중간 단계)에서 데이터가 불완전하게 전송될 경우 (예: `premium_value_proposition` 누락) | 상태 변화 로직이 중단되고, 이전 유효한 상태로 **Rollback**하거나, 현재 상태를 'Pending Review'로 명시함. |

## 3단계: 외부 API 연동 및 리스크 프로세서 테스트 (External Integration & Risk Processor Testing)

**목표:** 외부 서비스 호출 시 발생하는 네트워크 오류, 인증 실패, 또는 타 서비스의 응답 지연에 대한 시스템의 내구성을 확인한다.

| ID | 테스트 시나리오 | 외부 환경 조건 | 기대 결과 (Success Path) | 기대 결과 (Failure/Failover Path) | 우선순위 |
| :---: | :--- | :--- | :--- | :--- | :---: |
| **T3.1** | API 연결 실패 | 외부 리스크 데이터베이스(`RiskDB`)에 대한 연결을 일시적으로 차단하거나 응답 지연(Latency) 발생 유도. | `SafeExecutor`가 타임아웃(Timeout)을 감지하고, 캐시된 안전 기본값(Cached Safe Value)을 사용하여 다음 로직을 진행함. |
| **T3.2** | 권한/인증 실패 | 외부 API 호출 시 인증 토큰이 만료되거나 권한 부족 오류(`401`/`403`) 발생 유도. | 시스템은 인증 실패를 명확히 기록하고, 사용자에게 재인증을 요청하며, 데이터 접근을 **거부**함 (Fail). |
| **T3.3** | 리스크 프로세서 연동 검증 | 최종 계산 결과(Compliance Score)가 외부 규제 엔진과 통합될 때, 예측 불가능한 입력이 들어왔을 경우의 처리 흐름. | 시스템은 규제 기준(`76.15` 근거 등)에 기반하여 **최소 안전 점수**를 할당하고, 나머지 항목은 수동 검토 대기 상태로 전환함. |

## 4단계: 최종 통합 및 보고 (Final Integration & Reporting)

**목표:** 모든 단계에서 발생한 로그와 시스템 상태 변화를 통합하여 최종 안정성 보고서를 생성한다.

1.  **통합 로깅 확인:** 각 테스트 시나리오(`T1.x` ~ `T3.x`) 실행 후, 서버의 상세 에러 로그 및 시스템 이벤트 로그가 정확히 기록되었는지 검증한다. (특히 Safe Default Value 전환 지점)
2.  **KPI 측정:** 각 실패 경로에서 시스템이 **정상적으로 멈추거나(Fail), 안전하게 회피했는지(Failover)**에 대한 시간 측정치를 수집하여 KPI로 산출한다.
3.  **리포트 생성:** 최종 테스트 결과를 바탕으로, `BDS_PitchDeck_RiskSimulator_ValidationPlan_V1.md`의 통합 검증 체크리스트와 비교 분석하여 리스크 보고서를 작성한다.
