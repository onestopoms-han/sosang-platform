## B2B 서비스 안정성/예외 처리 핵심 용어 리서치 및 심리적 가치 분석

시스템 안정성과 예외 처리를 기술적인 측면뿐만 아니라, **사용자(소상공인)의 '통제권 회복 경험'**이라는 감성적 가치로 전환하여 신뢰를 구축하는 데 중점을 두었습니다. 다음은 리서치 결과입니다.

### 1. 강건성 (Robustness)

| 구분 | 내용 |
| :--- | :--- |
| **기술적 정의** | 시스템이 예상치 못한 입력, 오류, 부하 등 외부 환경 변화에 직면했을 때도 기능의 핵심 목표를 유지하며 정상적으로 작동하고 복구할 수 있는 능력. |
| **고객 전달 가치 (심리)** | **신뢰와 지속성 (Trust & Continuity)**: "어떤 상황에서도 서비스가 멈추지 않고 내 데이터를 안전하게 지켜준다"는 확신을 제공합니다. 이는 잠재적 손실에 대한 불안정성을 근본적으로 제거합니다. |
| **핵심 메시지** | **"흔들리지 않는 운영 기반"**: 시스템이 외부 충격에 흔들리지 않고 꾸준히 작동한다는 안정감을 전달합니다. |

### 2. 안전 기본값 (Safe Default Value)

| 구분 | 내용 |
| :--- | :--- |
| **기술적 정의** | 시스템 오류나 데이터 누락 발생 시, 임의로 잘못된 상태에 도달하는 것을 방지하기 위해 사전에 정의된 가장 보수적이고 안전한 초기 상태 값 또는 동작으로 자동 전환하는 로직. |
| **고객 전달 가치 (심리)** | **통제권 회복 (Control Recovery)**: 오류 발생 시 사용자가 당황할 여지를 없애고, 시스템이 스스로 '최악의 상황'을 방지하며 안전하게 대처하고 있음을 보여줍니다. 이는 불안정성(Anxiety)을 즉각적으로 감소시킵니다. |
| **핵심 메시지** | **"자동 안전장치"**: 문제가 발생해도 서비스가 스스로 통제권을 유지하며 피해를 최소화한다는 능동적인 보호막을 의미합니다. |

### 3. 자동 복구 메커니즘 (Self-Healing Mechanism)

| 구분 | 내용 |
| :--- | :--- |
| **기술적 정의** | 시스템 오류나 비정상 상태가 감지되었을 때, 사용자 개입 없이 시스템이 자체적으로 진단하고 문제를 해결하며 정상 상태로 복귀시키는 자동화된 프로세스. (예: 백업 로드 실행, 재시작, 데이터 동기화 등) |
| **고객 전달 가치 (심리)** | **편안함과 효율성 (Peace & Efficiency)**: 사용자가 문제 발생에 대해 신경 쓸 필요가 없다는 무의식적 안도감을 제공합니다. 이는 '관리 부담'을 덜어주고, 시간과 인지 자원을 절약해 줍니다. |
| **핵심 메시지** | **"걱정 없는 운영"**: 시스템이 스스로 문제를 해결하여 사용자가 핵심 업무에 집중할 수 있게 한다는 편리함과 신뢰를 동시에 전달합니다. |

| 용어 | 초점 영역 | 고객에게 주는 핵심 감성 가치 | 기술 vs. 경험 (UX) | 추천 상황 |
| :--- | :--- | :--- | :--- | :--- |
| **강건성 (Robustness)** | 시스템의 내구성/견고함 | 신뢰, 지속성 | 기술적 안정성을 기반으로 한 장기적 믿음 제공 | 서비스의 근본적인 품질을 강조할 때 |
| **안전 기본값 (Safe Default Value)** | 예외 상황에서의 초기 상태 설정 | 통제권 회복, 즉각적 안전 | 오류 발생 시 사용자의 불안을 즉시 해소하는 기능적 방어 | 오류 처리 로직과 UI의 연동을 설명할 때 |
| **자동 복구 메커니즘** | 문제 해결 프로세스 | 편안함, 효율성 | 사용자 개입 없이 이루어지는 편리하고 능동적인 경험 | 시스템의 선제적 대응 능력(AI/자동화)을 강조할 때 |
