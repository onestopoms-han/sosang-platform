## 통합 디자인 명세서: 시스템 통제권 회복 사용자 흐름 (Integrated Design Spec)

본 문서는 '데이터 기반의 시스템적 통제권 회복'이라는 핵심 가치를 시각적으로 구현하기 위한 최종 UI/UX 흐름 및 컴포넌트 상호작용 규칙을 정의합니다. 개발자가 모든 콘텐츠 요소가 하나의 유기적인 시스템처럼 작동하도록 구현할 수 있도록, 스토리텔링(Writer)과 데이터 인터랙션(Leo)을 통합하여 명세화합니다.

### 1. 디자인 철학 및 목표 (Design Philosophy & Goal)

*   **핵심 가치:** 불확실성에 대한 **시스템적 통제권 회복**.
*   **시각적 목표:** 사용자의 불안감(Pain)을 구체적인 데이터 상태 변화로 치환하고, 시스템의 개입(Control)을 통해 안정화되는 과정을 시각적으로 증명한다.
*   **톤 & 무드:** 전문적이고 차분하며, 위험 상황에서는 긴장감을 조성하는 명확한 대비를 사용한다 (골드 앰버 $\rightarrow$ 성장 녹색).

### 2. 핵심 UI 컴포넌트 정의 (Core Component Definitions)

| 컴포넌트 명 | 역할 | 시각적 표현 및 상태 변화 | 색상 체계 |
| :--- | :--- | :--- | :--- |
| **Pain Gauge** | 현재 시스템의 불안정성 수준을 실시간으로 측정하여 표시. | 원형 또는 선형 게이지 형태. 위험도가 높을수록 채워짐/색상이 강해짐. | **골드 앰버 ($\#FFC72C$)**: 고위험 (Pain) / **그린 ($\#38A169$)**: 안정화 (Control). |
| **Trust Widget** | A, B, C 등급의 시스템 무결성 상태를 비교하여 표시. | 세 개의 분리된 카드 또는 바 형태로 각 등급의 현재 상태(안정/불안)를 명확히 구분. | A: 안정 (🟢), B: 주의 (🟡), C: 위험 (🔴). |
| **System Status Bar** | 전체 시스템의 현재 상태 및 다음 행동 지침을 제공하는 컨트롤 영역. | 텍스트 기반의 명확한 상태 메시지 및 CTA 버튼. | 중립적인 회색/흰색 배경에 강조 색상으로 상태 표시. |

### 3. 사용자 흐름 및 인터랙션 로직 (User Flow & Interaction Logic)

전체 흐름은 **'Landing Page 스크롤'**과 **'데모 시퀀스(Dashboard)'**가 유기적으로 연결되어야 합니다.

#### A. 랜딩 페이지 흐름 (Writer 기반: Pain $\rightarrow$ Solution)

| 단계 | 사용자 행동 (스크롤/클릭) | 표시되는 마이크로 카피 | 연동되는 디자인 요소 | 목표 효과 |
| :--- | :--- | :--- | :--- | :--- |
| **1. 후크** | 화면 로딩 시점 (0-5초) | "당신의 공급망은 예측 불가능한 불안정성에 맡겨져 있습니까?" | Pain Gauge의 초기 상태(🔴 최대 위험). | 즉각적인 Pain Recognition 유도. |
| **2. 문제 정의** | 섹션 진입 시점 (5-15초) | "감(感)에 의존하는 관리, 숨겨진 비용과 리스크를 초래합니다." | Trust Widget이 불안정한 노란색/붉은색으로 표시됨. | 추상적 불안감을 구체적인 데이터 프레임으로 치환. |
| **3. 솔루션 소개** | 핵심 기능 시연 직전 (15-30초) | "데이터 기반의 시스템적 통제권, 이제 손에 쥐세요." | Pain Gauge가 Trust Widget 변화와 동시에 안정화되는 애니메이션 실행. | 해결책(Control) 제시 및 신뢰 구축. |
| **4. CTA** | 최종 버튼 클릭 | *[무료 진단 시작]* | 명확하고 강력한 행동 유도. | 다음 단계로의 자연스러운 전환. |

#### B. 데이터 인터랙션 시퀀스 (Leo 기반: Control 증명)

이 시퀀스는 랜딩 페이지에서 제시된 문제를 시스템적으로 해결하는 과정을 **시각화**합니다.

| 시간대 | 시각적 연출 (Visual Direction) | 핵심 상호작용 규칙 | 강조 메시지 (Audio/Narration) |
| :--- | :--- | :--- | :--- |
| **0:00 - 0:30** | **Pain Recognition:** Pain Gauge가 🔴로 고정. Trust Widget이 A, B, C 모두 불안정한 노란색(🟡). | 데이터 입력 시각화에 마찰(Lag) 효과 적용. (불안정한 상태 강조) | "직감은 통하지 않습니다. 예측은 오차를 만듭니다." |
| **0:30 - 1:15** | **Quantifying the Problem:** Trust Widget의 A등급이 안정적인 녹색(🟢)으로 전환되는 애니메이션 실행. | 시스템 분석 완료 시, 데이터 변화에 따른 UI가 즉시 반응하도록 설정. (A등급의 안정화 강조) | (내레이션은 잠시 멈추고 시각적 변화에 집중). |
| **1:15 - End** | **Solution Reveal:** Pain Gauge가 🟢로 전환되며 전체 시스템이 안정 상태(Green State)로 진입. | 모든 Trust Widget이 녹색으로 일괄 전환. 최종적으로 System Status Bar가 '통제권 회복 완료' 메시지 표시. | "데이터 기반의 시스템적 통제권, 이제 손에 쥐세요." (CTA 유도). |

### 4. 개발자를 위한 기술 명세 요약 (Handoff Summary for Developer)

1.  **상태 관리:** 모든 시각적 요소(Gauge, Widget)는 백엔드 데이터 상태(A/B/C 등급, 불안정성 지수)에 따라 **실시간으로 바인딩**되어야 한다.
2.  **애니메이션 로직:** Pain $\rightarrow$ Control 전환 구간에서는 **데이터 변화와 시각적 피드백 사이의 인과 관계**를 명확히 하여 애니메이션을 구현한다. (예: 데이터가 긍정적으로 변할 때, 불안정성 지표는 즉시 감소하며 색상이 녹색으로 점진적 변화).
3.  **컴포넌트 배치:** Trust Widget은 중앙에 배치하여 핵심 비교 정보를 제공하고, Pain Gauge는 시각적 긴장감을 유지하도록 화면 상단 또는 주요 섹션에 배치한다.
