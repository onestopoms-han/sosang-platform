## 2. '제외 품목' 목록 및 연관 HS 코드 매핑 구조 (Exception Mapping)

### 2.1. 제외 품목 마스터 리스트 (Exclusion Master List)

| 카테고리 | 품목 설명 (사용자 입력 예시) | 시스템 처리 방식 | 연관 HS 코드 (Reference Code) |
| :--- | :--- | :--- | :--- |
| **장신구류** | 보석, 시계, 액세서리 등 미적 가치가 주된 품목인 체인 형태. | 분류 중단 및 사용자 경고 메시지 출력. | 7113 (보석류) 또는 7116 (기타 금속제품) |
| **공구류** | 드릴, 렌치, 클램프 등 기능적 사용을 위한 도구의 체인 형태. | 분류 중단 및 사용자 경고 메시지 출력. | 8205 (공구) 또는 기타 공구 관련 HS 코드 |

### 2.2. 매핑 구조 정의 (Mapping Structure for API Layer)

API 요청 시, 입력된 `item_details` 리스트에 대해 다음과 같은 **Two-Stage Validation** 프로세스를 거치도록 시스템 로직을 설계합니다.

1.  **Stage 1: Exclusion Check:** 각 항목(`item_details`)이 2.1의 제외 목록에 해당하는지 확인한다.
    *   **IF Match:** `validation_status` = `EXCLUDE`, `classification_reason` = "제외 품목으로 분류됨", `risk_score` = 0.
2.  **Stage 2: Core Classification (If Not Excluded):** 항목이 링크체인 형태를 만족하는지, 재질과 공정 정보를 기반으로 7315 코드를 도출한다.
    *   **IF Pass:** `validation_status` = `PASS`, `hs_code` = [Calculated HS Code], `classification_reason` = "형태/공정 기반 분류 완료".
    *   **IF Fail (TC-002, TC-004 등):** `validation_status` = `FAIL`, `hs_code` = "N/A", `classification_reason` = "링크체인 형태가 아니며, 기타 분류 필요(예: 7326 또는 84류)".

## 3. 예외 처리 로직 정의서 (Error Handling Logic Definition)

시스템이 예측 불가능한 입력에 대해 일관되고 책임감 있는 응답을 제공하도록 하는 최종 규칙입니다. 이는 **인지 부하 이론(Cognitive Load Theory)**과 **행동 가능한 실행 계획(Actionable Blueprint)** 원칙을 반영하여 설계되었습니다.

### 3.1. 오류 유형별 처리 흐름도 (Flowchart)

| 입력 조건 | 시스템 반응 (Error Handling Logic) | 사용자 피드백 (UX Flow) | 관련 지표 연동 |
| :--- | :--- | :--- | :--- |
| **Case A: 명확한 제외** (예: 장신구, 공구) | Stage 1 (Exclusion Check) 즉시 실행. HS 코드 계산 중단. | "분류 불가: 해당 품목은 [제외 목록]에 속하므로 분류를 중단합니다. 관련 코드는 [Reference Code]입니다." | `risk_score` = 0, `status` = EXCLUDE |
| **Case B: 형태 불일치** (예: 파이프 연결 구조) | Stage 2 (Core Classification) 실행 후 실패 판정. | "분류 실패: 입력된 항목은 링크체인(7315)의 물리적 형태 기준을 충족하지 않습니다. [대안 분류]를 시도하시겠습니까?" | `risk_score` = High, `status` = FAIL |
| **Case C: 데이터 부족** (예: 재질/공정 정보 누락) | Stage 2 실행 전 필수 필드 검증 실패. | "분류에 필요한 핵심 정보(재질 또는 공정)가 누락되었습니다. [필수 정보]를 추가해 주십시오." | `risk_score` = Medium, `status` = PENDING |
| **Case D: 성공적 분류** (예: TC-001) | Stage 2 성공. | "분류 완료: HS 코드 [7315.10]으로 확정되었습니다. 근거는 [형태/공정 기반 분류]입니다." | `risk_score` = Low, `status` = PASS |

### 3.2. 최종 시스템 책임 (System Accountability)

시스템은 **분류 오류**를 발생시킬 때 단순히 실패를 반환하는 것이 아니라, **왜 실패했는지(Reason)**와 **다음 행동(Actionable Blueprint)**을 함께 제공하여 사용자가 스스로 문제를 해결하고 통제권을 회복하도록 돕는다. 이는 '감성적 리스크 관리' 목표에 부합한다.
