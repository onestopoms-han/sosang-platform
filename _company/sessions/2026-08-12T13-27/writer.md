# 데이터 사전 및 사용 가이드 (Data Dictionary & Usage Guide)

## 🎯 목적
본 문서는 `Authority Flow Engine`의 핵심 입력 데이터인 '고위험 시나리오 데이터베이스'를 개발자(Developer)와 디자이너(Designer)가 시스템 구현에 활용하기 위해 작성되었습니다. 이 문서는 각 리스크 요인이 최종 권위 흐름(Authority Flow) 점수 계산에 어떻게 반영되는지, 그리고 데이터셋 내 모든 변수의 의미를 명확히 정의하여 **논리적 검증 단계**를 수행하는 것을 목표로 합니다.

## ⚙️ 시스템 개요: Authority Flow 메커니즘
시스템은 법적 불확실성(Risk Factor)을 정량화하고 이를 '권위 흐름 점수(Authority Flow Score)'로 변환합니다. 이 가이드라인은 입력 데이터가 어떻게 이 변환 과정을 지원하는지 설명합니다.

## 📚 데이터 사전 (Data Dictionary)

| 필드명 | 타입 | 설명 | 사용 목적 |
| :--- | :--- | :--- | :--- |
| **id** | String | 각 시나리오의 고유 식별자 (예: TC001) | 시스템 내부 참조 및 추적 |
| **상품 정보** | String | 해당 시나리오에서 다루는 구체적인 상품 또는 재료에 대한 설명. | 리스크의 대상 명확화 |
| **법적 불확실성 요인** | String | 해당 시나리오에서 발생하는 핵심 법적/규제적 불확실성의 내용 (예: HS 분류, 원산지 규정 해석). | 위험의 근원 정의 |
| **리스크 가중치 점수 (1~10점)** | Integer | 정의된 법적 불확실성 요인이 내포하는 잠재적 리스크 수준. (1점: 낮음, 10점: 매우 높음) | 최종 권위 흐름 계산의 핵심 입력값 |
| **해당 위험의 법적 근거 조항** | String | 해당 리스크를 뒷받침하는 구체적인 관세법, FTA 협정, 또는 실무 지침의 명시 조항. | 권위(Authority)의 출처 제시 및 검증 기준 제공 |

## ⚖️ 리스크 가중치 부여 규칙 (Weighting Rules)

`리스크 가중치 점수 (1~10점)`는 다음의 **법적 근거**와 **실무적 복잡성**에 기반하여 결정되어야 합니다. 개발자는 이 규칙을 코드로 구현해야 합니다.

1.  **법적 근거 우선 적용:**
    *   `해당 위험의 법적 근거 조항`에 명시된 규정(관세법, FTA 등)이 변경되거나 해석이 모호할 경우, 기본 점수는 최소 **7점 이상**으로 설정되어야 합니다. (고위험 분류)
    *   단순한 행정 절차상의 불확실성(예: 통보 지연)은 3~4점 범위로 설정합니다.

2.  **복잡성 반영:**
    *   HS 분류의 세분화 요구사항, 원산지 규정(ROO) 해석의 주관적 판단이 필요한 경우 가중치를 상향 조정합니다. (예: TC003 - HS 분류의 본질적 기능 고려)
    *   실시간 데이터 예측 실패 위험 등 **금전 손실 위험**이 직접적으로 연관된 경우, 점수를 최대치(10점)에 가깝게 설정합니다. (예: TC004 - 관세율 변동성 예측 실패)

3.  **권위 흐름과의 연결:**
    *   높은 리스크 가중치($\geq 8$)는 '통제 상실'의 위험이 크다는 것을 의미하며, 이는 **Authority Flow 점수를 급격히 하락**시키는 주요 요인으로 설정합니다.

## 🖥️ 디자이너 및 개발자를 위한 사용 지침 (Implementation Guide)

### 💡 디자이너 지침 (UX/UI Focus)
1.  **시각화 우선:** 최종 사용자에게는 '리스크 점수'와 '법적 근거 조항'이 명확하게 시각화되어야 합니다. 추상적인 설명보다 **'어떤 법률 조항 때문에 이 위험이 발생했는지'**를 함께 제시해야 권위를 확보합니다.
2.  **색상 코딩:** 리스크 점수에 따라 색상 체계를 적용하십시오. (예: 8~10점 = Critical Red, 5~7점 = Warning Yellow)

### 💻 개발자 지침 (Logic Focus)
1.  **API 설계:** 각 `test_case`는 입력으로 받아 최종 권위 흐름 점수($AF_{score}$)를 산출하는 함수로 매핑되어야 합니다. $AF_{score} = f(\text{Risk Weight}, \text{Authority Input})$.
2.  **데이터 정합성 검증:** 시스템 구현 전, 모든 `test_cases`에 대해 **최소 3가지 이상의 법적 근거 조항**이 정확히 연결되어 있는지 교차 검증 로직을 추가하십시오.
3.  **변수 관리:** `상품 정보`와 `법적 불확실성 요인`은 동적으로 확장될 수 있도록 데이터베이스 스키마를 유연하게 설계해야 합니다.
