# 📝 플랫폼 통합 테스트 (UAT) QA 프로토콜: 자문단 소집 및 최종 접수 흐름

이 프로토콜은 사용자가 플랫폼 내 AI 에이전트와의 상호작용을 통해 최종 결과물을 도출하고 외부 서비스(변호사)로 연동하는 전체 과정을 검증하기 위해 설계되었습니다.

## 🎯 프로세스 요약 (Summary)

| 단계 | 사용자 액션 | 예상 시스템 상태 변화 (State Transition) | 필수 검증 항목 (Checklist Item) | 에이전트 피드백 루프 |
| :---: | :--- | :--- | :--- | :--- |
| **1** | `http://localhost:3000/` 접속 | 초기 로딩 상태 $\rightarrow$ 준비 상태 | 서버 연결 및 UI 정상 표시 여부 | - |
| **2** | '📝 샘플 사건 불러오기' 클릭 | 데이터 로드 대기 $\rightarrow$ 자료 선택 모드 | 샘플 데이터 목록의 정확성 및 접근 권한 확인 | 시스템 (데이터 제공) |
| **3** | '자문단 소집 및 1차 진단 개시' 클릭 | 진단 프로세스 시작 $\rightarrow$ 자문단 활성화 대기 | 자문단 호출 성공 여부, 초기 세팅 완료 여부 | 자문단 에이전트 (진단 시작 알림) |
| **4** | 로딩 애니메이션 대기 | 처리 중 상태 유지 | 2초 로딩 애니메이션의 부드러움 및 안정성 | 시스템 (처리 진행 상황 시각화) |
| **5** | 채팅창에 질문 입력 후 '전송' | 사용자 질의 등록 $\rightarrow$ 에이전트 응답 대기 | 메시지 전송 성공 여부, 입력된 내용이 정확히 전달되었는지 | 자문단 에이전트 (응답 생성 및 송신) |
| **6** | 에이전트 동적 응답 관찰 | 에이전트 처리 중 $\rightarrow$ 실시간 대화 모드 | 응답 지연 시간(Latency), 답변 내용의 논리적 일관성 | 자문단 에이전트 (실시간 대화) |
| **7** | '종합 결론 리포트 초안 빌드' 클릭 | 보고서 생성 시작 $\rightarrow$ 최종 결과물 준비 모드 | 최종 리포트 빌드 성공 여부, 데이터 취합 오류 여부 | 시스템 (보고서 생성) |
| **8** | 탭 전환 (권고안/의견) | 인터랙티브 레이아웃 활성화 | 두 탭 간 내용 표시의 정확성 및 UI 반응성 | 보고서 컴포넌트 (레이아웃 동기화) |
| **9** | '자격사 최종 검토 & 공인 서명 신청' 클릭 | 법적 검토 모드 $\rightarrow$ 서명 요청 상태 | 최종 검토 항목 누락 여부, 서명 절차의 유효성 | 변호사 에이전트 (검토 결과 제시) |
| **10** | '프로그램 즉시 접수' 선택 | 외부 연동 시작 $\rightarrow$ 접수 대기 모드 | 이민우 변호사 연결 성공 여부, 데이터 매핑 정확성 | 이민우 변호사 에이전트 (접수 요청 수신) |
| **11** | 최종 서명 화면 확인 | 최종 승인 상태 $\rightarrow$ 완료/확정 상태 | 최종 서명 화면의 법적/기술적 무결성 | 시스템 및 변호사 에이전트 (최종 기록 보존) |
| **12** | 파일 저장 요청 (`onestop_final_presentation_loop.webp`) | 결과물 내보내기 $\rightarrow$ 파일 저장 완료 | 지정된 경로에 파일이 성공적으로 저장되었는지 | 시스템 (파일 생성 및 경로 반환) |

## ⚙️ 세부 검증 항목 및 피드백 루프 상세

### 1단계 ~ 4단계: 진단 개시 및 초기 대기 단계
*   **핵심 목표:** 플랫폼 접속부터 자문단 활성화까지의 기술적 안정성 확인.
*   **검증 포인트:** 서버 응답 시간, UI 컴포넌트 로딩 상태.
*   **피드백 루프:** 시스템이 모든 API 호출 및 초기 설정이 성공적으로 완료되었는지 자체 검증 후 다음 단계로 진행 여부를 결정합니다.

### 5단계 ~ 6단계: 질의 및 실시간 소통 단계 (가장 중요)
*   **핵심 목표:** 사용자의 의도를 정확히 이해하고 에이전트들이 논리적으로 상호작용하는지 확인.
*   **검증 포인트:** 사용자 입력(Prompt)에 대한 응답 생성 시간, 답변 내용의 맥락 적합성(Contextual Relevance).
*   **피드백 루프:** 사용자의 후속 질문이나 명확화 요청이 있다면, 에이전트들이 해당 감정 KPI(`Pain Gauge`, `Trust Index`) 변화를 기반으로 추론하여 응답하도록 설계되어야 합니다.

### 7단계 ~ 8단계: 보고서 빌드 및 시각화 단계
*   **핵심 목표:** 복잡한 분석 결과를 사용자가 원하는 형태로 시각적/구조적으로 제공하는지 확인.
*   **검증 포인트:** '합동 권고안'과 '변호사 의견' 탭 전환 시 레이아웃이 깨지지 않고 일관성을 유지하는지 (디자인 토큰 준수).
*   **피드백 루프:** 데이터 기반의 시각화 로직(`Trust Widget`, `PainGauge` 연동)이 정확하게 작동하고 있는지 확인하여, 숫자가 아닌 감성적 상태 변화가 명확히 전달되는지 점검합니다.

### 9단계 ~ 12단계: 최종 승인 및 외부 연동 단계
*   **핵심 목표:** 법적/실행 단계의 무결성과 외부 시스템(변호사)과의 데이터 교환 정확성 확보.
*   **검증 포인트:** 서명 프로세스의 무결성, 변호사 에이전트에게 전달되는 정보의 완전성, 최종 파일 저장 경로 및 포맷의 정확성.
*   **피드백 루프:** 모든 단계에서 발생한 '감정적 경고 시스템'이 법적/실행적 결과에 영향을 미치는지 역추적 검토합니다.
