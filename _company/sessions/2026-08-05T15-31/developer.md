## 🏗️ 시스템 아키텍처 및 데이터 플로우 설계 (MVP Blueprint)

우리가 구축할 시스템은 크게 세 가지 핵심 레이어(Layer)와 하나의 중앙 처리 엔진(Core Engine)으로 구성됩니다.

### 1. High-Level Architecture Diagram (개념도)

아래는 시스템의 전체적인 흐름을 나타내는 개념 다이어그램입니다.

```mermaid
graph TD
    A[사용자 입력: 품목 속성] --> B{입력 검증 및 매핑};
    B --> C[Divergence Logic Engine];
    C --> D{규제 비교 결과 도출 (Red Zone 식별)};
    D --> E[리스크 평가 모듈];
    E --> F[Actionable Blueprint 생성];
    F --> G[프론트엔드: 리스크 시각화 & 행동 버튼];

    subgraph Data Layer (데이터 저장소)
        H[HS 코드/규정 데이터셋]
        I[품목 속성 메타데이터]
    end

    C -- 참조 --> H;
    B -- 비교 --> I;
```

### 2. 핵심 데이터 플로우 상세 정의

이 흐름은 사용자가 어떤 행동을 할 때, 시스템 내부에서 어떤 일이 벌어지는지를 명확히 정의합니다.

| 단계 | 프로세스 명칭 | 입력 (Input) | 처리 로직 (Logic) | 출력 (Output) | 관련 데이터셋 |
| :--- | :--- | :--- | :--- | :--- | :--- |
| **Step 1** | **입력 수집 (Input Collection)** | 사용자가 입력한 품목의 상세 속성 (재질, 용도, 제조 공정 등) | **데이터 유효성 검사:** 입력 데이터가 시스템 요구사항(Schema)을 충족하는지 확인. | 정제된 **품목 속성 벡터** | I (품목 속성 메타데이터) |
| **Step 2** | **규제 매핑 (Regulation Mapping)** | 정제된 품목 속성 벡터 + 목표 국가/지역 설정 | **Divergence Logic 실행:** 입력 속성과 DB 내 규제 매트릭스를 비교하여 충돌 지점 식별. | **규제 충돌 리스트 (Red Zone)** | H (HS 코드/규정 데이터셋) |
| **Step 3** | **리스크 평가 (Risk Assessment)** | 규제 충돌 리스트 + 사용자가 설정한 가중치 (예: 환경 기준 중요도, 관세율 민감도) | **가중치 기반 위험 점수 산출:** 단순 충돌을 넘어 비즈니스 영향도를 정량화. | **위험 등급 (A/B/C)** | - |
| **Step 4** | **행동 가이드 생성 (Action Guide Generation)** | 위험 등급 + 규제 충돌 리스트 | **Actionable Blueprint 생성:** 위험 수준에 따라 가장 합리적인 '다음 행동' 옵션(예: A안, B안)을 제시. | **최적의 다음 행동 로드맵** | - |

### 3. 필수 API 통합 지점 (API Integration Points)

이 플로우를 실제로 코드로 구현하기 위해 필요한 핵심 API 엔드포인트와 데이터베이스/서비스 간의 연결 지점을 정의합니다.

1.  **`POST /api/diagnose` (핵심 진단 엔드포인트):**
    *   **목적:** 사용자의 입력(품목 속성)을 받아 최종 위험 평가 및 행동 가이드를 반환하는 단일 API입니다.
    *   **입력:** `product_attributes`, `target_jurisdiction` (사용자 설정)
    *   **출력:** `{ "risk_level": "B", "divergence_points": [...], "actionable_blueprint": [...] }`

2.  **`GET /api/data/divergence_logic` (규제 데이터 조회):**
    *   **목적:** Step 2에서 필요한 규제 비교 데이터를 조회합니다. 이 부분은 **HS 코드 데이터셋(H)**에 대한 검색 로직이 통합되어야 합니다.

3.  **`POST /api/validate_schema` (입력 유효성 검증):**
    *   **목적:** Step 1에서 입력된 품목 속성이 시스템이 요구하는 모든 필드를 정확히 포함하는지 최종적으로 확인합니다. **(데이터 무결성 확보)**
