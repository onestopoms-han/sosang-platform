### 2. 리스크 점수 모델 통합 변수 제안 (Actionable Proposal)

조사된 법규 변화를 바탕으로, 기존의 **Authority Flow Risk Score**에 통합할 수 있는 새로운 동적 변수를 다음과 같이 제안합니다. 이 변수들은 외부 데이터 연동(Adapter Pattern)을 통해 확보되어야 합니다.

| 제안 변수명 | 산출 근거 (Input Data Source) | 리스크 영향도 | Hard Stop 임계값 조정 기여 |
| :--- | :--- | :--- | :--- |
| **Regulatory Volatility Index ($\text{RVI}$)** | 특정 법규 개정 빈도 및 내용의 복잡성 지수 | 중/고 | $\text{RVI} > \text{Threshold}_{\text{Legal}}$ 일 경우, 시스템이 자동으로 '경고' 단계를 넘어 'Hard Stop'을 권고하도록 임계값 조정. |
| **Sanction Exposure Score ($\text{SES}$)** | 당사 거래 대상 국가/개체에 대한 실시간 제재 리스트 변경 여부 | 최상 (Critical) | $\text{SES} \ge 1$ 일 경우, 즉시 Hard Stop을 활성화하는 비가역적 트리거로 사용. |
| **Tariff Fluctuation Delta ($\Delta T$)** | 기준 품목의 최근 3개월 관세율 변동 폭 | 중 | 예상 이익 변동성($\text{Margin Volatility}$) 계산 시, $\Delta T$를 핵심 가중치로 반영하여 재무적 손실 예측 정확도 향상. |
| **Compliance Burden Factor ($\text{CBF}$)** | 새로운 ESG 또는 공급망 실사 요구사항의 적용 강도 | 중 | 시스템이 제시하는 'Actionable Blueprint'에 필수적인 규제 준수 단계를 추가하여, 단순 리스크가 아닌 '준수 경로'를 제공. |

3.  **중앙 영역 (Main Visualization Area):** 핵심 데이터 게이지와 권한 흐름의 상호작용 시각화.
4.  **우측 패널 (Detail Panel):** 현재 선택된 경로에 대한 상세 분석, 근거(Source) 및 실행 옵션 표시.

### B. 핵심 컴포넌트 상세 스펙

#### 1. 리스크 게이지 (Risk Gauge Component)
*   **위치:** 중앙 영역 상단
*   **구성:** 원형 또는 선형 게이지 형태로 구현.
    *   **중앙 값:** 현재 **Risk Score**를 가장 크게 표시 (`Control Score: XX%`). 색상은 현재 상태(Red, Amber, Green)에 따라 동적으로 변경.
    *   **경계선:** Red Zone (최고 위험), Amber Zone (주의), Green Zone (안정). 이 세 영역은 배경색으로 명확히 구분되어야 합니다.
    *   **하단 레이블:** 시스템 지표 설명(`시스템 통제권 확보율: XX%`)을 Rich Gold 색상과 작은 폰트로 표시하여 과학적 근거를 뒷받침합니다.

#### 2. 권한 확보 경로 시각화 (Authority Flow Visualization)
*   **위치:** 좌측 사이드바 및 중앙 영역 연결
*   **형태:** 노드 기반의 **인터랙티브 그래프(Node-based Graph)** 형태.
    *   **노드:** 각 단계(예: Pain Point 인지 $\rightarrow$ 데이터 수집 $\rightarrow$ 권한 확보)를 원형 또는 사각형 박스로 표현.
    *   **엣지 (Edge):** 노드 간의 연결선으로, **권한 확보 경로**를 나타냄. 엣지의 색상은 해당 단계에서 발생한 리스크 수준(Red/Amber/Green)에 따라 결정됨.
    *   **인터랙션:** 사용자가 특정 노드를 클릭하면, 우측 상세 패널에 해당 단계의 데이터와 다음 단계로 나아갈 수 있는 실행 옵션이 즉시 표시되어야 합니다.

#### 3. 실행 및 근거 패널 (Action & Evidence Panel)
*   **위치:** 우측 패널
*   **내용 구성:**
    1.  **현재 위치 요약:** 사용자가 현재 Authority Flow의 어느 지점에 있는지 명확히 표시.
    2.  **핵심 통제 변수:** 해당 단계에서 결정해야 할 핵심 법적/재무 변수 목록 (예: `Regulatory Vola` 등).
    3.  **근거 제시 영역:** 선택된 데이터(Score, Flow)에 대한 모든 근거(`[근거: ...]`)를 명확하게 배치하여 신뢰도를 확보.

## 4. 디자인 가이드라인 업데이트 요약

1.  **레이아웃 우선순위:** **Flow (흐름)** $\rightarrow$ **Score (점수)** $\rightarrow$ **Evidence (근거)** 순으로 시각적 계층 구조를 설정합니다.
2.  **색상 사용 규칙 확정:** Red/Amber/Green의 의미를 리스크 임계값과 직접 연결하여, 색상이 감정적 반응을 유발하는 동시에 행동을 촉구하도록 설계합니다. (Red = Stop / Amber = Review / Green = Proceed).
3.  **데이터 강조:** 모든 핵심 수치(`Control Score`, `Article ID`)는 **Rich Gold**로 강조하고, 시스템 지표 설명은 작은 폰트와 함께 배치하여 시각적 강조가 '과학적 근거'에 기반함을 명시합니다.

<create_file path="backend/src/risk_service.py">
class RiskService:
    """
    Authority Flow 기반 리스크 점수 계산 및 권한 경로 분석 서비스.
    법적 변수와 감성적 흐름을 통합하여 최종 리스크 점수를 산출합니다.
    """
    def __init__(self, risk_variables: dict):
        self.risk_variables = risk_variables

    def calculate_risk_score(self, diagnosis_data: dict) -> dict:
        """
        입력된 진단 데이터와 동적 법규 변수를 통합하여 최종 리스크 점수와 권한 경로를 계산합니다.
        [근거: 코다리 개인 메모리, sessions/2026-05-23T12-01/developer.md]
        """
        base_risk = diagnosis_data.get('base_risk', 0.5)  # 기본 진단 위험도 (예: 손실 위험도 High -> 0.8)
        regulatory_impact = self._calculate_regulatory_impact(diagnosis_data)
        flow_adjustment = self._calculate_flow_adjustment(diagnosis_data)

        # 최종 리스크 점수 계산 로직
        final_score = base_risk + regulatory_impact + flow_adjustment
        
        # 권한 경로 결정 (Authority Flow)
        authority_path = self._determine_authority_flow(final_score, diagnosis_data)

        # UI/UX에 필요한 감성적 상태 매핑
        emotional_state = self._map_to_emotional_state(final_score)

        return {
            "risk_score": round(final_score, 3),
            "authority_flow": authority_path,
            "emotional_state": emotional_state,
            "details": {
                "regulatory_contribution": regulatory_impact,
                "flow_adjustment": flow_adjustment,
                "base_risk": base_risk
            }
        }

    def _calculate_regulatory_impact(self, data: dict) -> float:
        """법적 변수를 기반으로 리스크에 미치는 영향을 계산합니다."""
        # 실제 구현에서는 self.risk_variables와 diagnosis_data를 매핑하여 복잡한 가중치 계산을 수행해야 함.
        # 현재는 Mockup 데이터 기반으로 단순 합산 로직을 제시합니다.
        regulatory_score = 0.0
        if data.get('regulatory_vars'):
            for var, value in data['regulatory_vars'].items():
                # 예: Regulatory Volatility가 높으면 리스크 가중치 증가
                regulatory_score += value * self.risk_variables.get(var, 1.0)
        return regulatory_score

    def _calculate_flow_adjustment(self, data: dict) -> float:
        """사용자 상태 변화에 따른 흐름 조정 값을 계산합니다."""
        # Flow 데이터 기반으로 잠재적 기회/위험을 반영하여 점수를 미세 조정합니다.
        if data.get('story_flow_status') == 'Control':
            return -0.1  # 통제 단계에서는 리스크를 낮추는 보정치 적용
        elif data.get('story_flow_status') == 'Awareness':
            return 0.2   # 인지 단계에서는 주의를 높이는 보정치 적용
        else: # Anxiety/Focus
            return 0.0

    def _determine_authority_flow(self, score: float, diagnosis: dict) -> str:
        """최종 점수를 기반으로 권한 확보 경로를 결정합니다."""
        if score >= 3.5:
            return "Critical Stop (Red Zone)"  # 위험 임계값 초과
        elif score >= 2.0:
            return "Warning Path (Amber Zone)" # 선제적 조치 필요
        else:
            return "Control Path (Green Zone)" # 안정 상태

    def _map_to_emotional_state(self, score: float) -> str:
        """점수를 기반으로 사용자에게 제시할 감정적 상태를 매핑합니다."""
        if score >= 4.0:
            return "Anxiety"  # Red Zone에 근접 (불안)
        elif score >= 2.5:
            return "Focus"    # Amber Zone (집중)
        else:
            return "Control"  # Green Zone (안정/통제)

# --- Mockup Data & Initialization ---
risk_vars = {
    "Regulatory Volatility": 1.5,  # 법규 변동성이 높을수록 리스크 가중치 증가
    "Financial Loss Risk": 2.0,    # 재무적 손실 위험이 클수록 가중치 증가
}

# 테스트용 진단 데이터 (Mockup)

class RiskService:
    """
    Authority Flow Risk Score 계산 및 법적 근거 기반 위험 분석 서비스.
    법적 근거 조항과 가중치를 통합하여 선제적 위험 방어 보험료 개념을 반영합니다.
    """
    def __init__(self, weights: dict, legal_db: dict):
        # 가중치 설정 (예: 법적 리스크와 시장 리스크의 비율)
        self.weights = weights
        # 법률 데이터베이스 로드 (Article ID 및 관련 벌금/위험 데이터 포함)
        self.legal_db = legal_db

    def calculate_risk_score(self, diagnosis_input: dict) -> dict:
        """
        진단 입력과 법적 데이터를 기반으로 최종 위험 점수를 계산합니다.
        """
        base_risk = 0.0
        weighted_legal_risk = 0.0

        # 1. 기본 리스크 계산 (Diagnosis Input 기반)
        if 'financial_exposure' in diagnosis_input:
            base_risk += diagnosis_input['financial_exposure'] * self.weights.get('market_weight', 1.0)
        if 'compliance_gap' in diagnosis_input:
            base_risk += diagnosis_input['compliance_gap'] * self.weights.get('legal_weight', 1.5)

        # 2. 법적 근거 기반 리스크 가중치 적용 (Article ID 통합)
        legal_multiplier = 1.0
        if 'article_ids' in diagnosis_input and diagnosis_input['article_ids']:
            for article_id in diagnosis_input['article_ids']:
                # 법적 데이터베이스에서 해당 조항의 위험 가중치를 조회
                risk_factor = self.legal_db.get(article_id, {}).get('risk_multiplier', 1.0)
                legal_multiplier += risk_factor
            
            weighted_legal_risk = legal_multiplier * self.weights.get('compliance_weight', 2.0)

        # 최종 위험 점수 계산 (가중치 기반 통합)
        final_score = (base_risk * self.weights.get('market_weight', 1.0)) + (weighted_legal_risk * self.weights.get('compliance_weight', 2.0))
        
        # Hard Stop 임계값 적용 로직
        hard_stop_threshold = self.legal_db.get('hard_stop_threshold', 50)
        hard_stop_status = "Low Risk"
        if final_score >= hard_stop_threshold:
            hard_stop_status = "Hard Stop - Immediate Action Required"

        return {
            "final_risk_score": round(final_score, 2),
            "weighted_legal_component": round(weighted_legal_risk, 2),
            "risk_level": hard_stop_status,
            "details": {
                "base_risk": round(base_risk, 2),
                "legal_contribution": round(weighted_legal_risk, 2),
                "applied_threshold": hard_stop_threshold
            }
        }

from typing import List, Dict, Any, Tuple
from pydantic import BaseModel, Field

# 1. 입력 데이터 스키마 정의 (Input Schema)
class RiskFactor(BaseModel):
    """단일 리스크 요인에 대한 데이터 구조."""
    factor_name: str = Field(..., description="리스크 요인의 명칭 (예: 법적 근거, 위반 정도)")
    value: float = Field(..., description="해당 요인의 정량적 값 (0.0 ~ 100.0)")
    frequency_weight: float = Field(..., description="발생 빈도 가중치 (0.1 ~ 1.0)")
    legal_article_id: str = Field(..., description="관련 법적 조항 ID")

class RiskInputData(BaseModel):
    """리스크 점수 계산을 위한 전체 입력 데이터 스키마."""
    contextual_data: Dict[str, Any] = Field(..., description="사용자 또는 상황에 대한 맥락 데이터 (예: 시장 위험도, 규제 복잡성)")
    factors: List[RiskFactor] = Field(..., description="개별 리스크 요인 목록")
    base_risk_threshold: float = Field(50.0, description="시스템 안정성을 위한 기본 임계값")

# 2. 가중치 기반 리스크 점수 산정 알고리즘 (Algorithm)
class RiskCalculator:
    """리스크 점수를 계산하고 행동 지침을 도출하는 핵심 로직 클래스."""

    def __init__(self, weights: Dict[str, float]):
        """
        가중치 맵 초기화.
        weights: 리스크 요인 유형별 가중치 (예: '법적_위반' : 3.0)
        """
        self.weights = weights

    def calculate_risk_score(self, input_data: RiskInputData) -> float:
        """
        입력 데이터를 기반으로 최종 리스크 점수를 계산합니다. (가중치 적용)
        """
        total_weighted_risk = 0.0
        
        for factor in input_data.factors:
            # 1. 기본 위험도 계산: 값 * 빈도 가중치
            base_risk = factor.value * factor.frequency_weight
            
            # 2. 법적 근거 가중치 적용 (사용자가 정의한 유형별 가중치)
            factor_type = factor.factor_name.split('_')[0] # 예: '법적_위반' -> '법적'
            weight = self.weights.get(factor_type, 1.0) # 기본값 1.0 적용
            
            weighted_risk = base_risk * weight
            total_weighted_risk += weighted_risk
        
        # 최종 점수 정규화 및 임계값 처리 (선제적 위험 방어 보험료 개념 반영)
        final_score = min(100.0, total_weighted_risk * 1.5) # 1.5배 증폭 및 최대 100점 제한
        
        return round(final_score, 2)

    def generate_actionable_blueprint(self, score: float, input_data: RiskInputData) -> Dict[str, Any]:
        """
        최종 점수에 따라 '다음 행동'과 해당 법적 조항을 매핑하여 출력합니다.
        """
        action_blueprint = {
            "score": score,
            "status": "Normal",
            "action": "모니터링 지속",
            "article_id": "N/A"
        }

        # 리스크 점수 기반 행동 로직 (Authority Flow 구현)
        if score >= input_data.base_risk_threshold * 1.5:
            action_blueprint["status"] = "Critical"
            action_blueprint["action"] = "즉각적 법적 검토 및 Hard Stop 임계값 확인"
            # 가장 심각한 리스크에 해당하는 Article ID를 매핑 (가정)
            if any(f.legal_article_id == 'Law_Violation_Critical' for f in input_data.factors):
                action_blueprint["article_id"] = "Law_Violation_Critical"
            else:
                action_blueprint["article_id"] = "Legal_Review_Required"
        elif score >= input_data.base_risk_threshold:
            action_blueprint["status"] = "Warning"
            action_blueprint["action"] = "선제적 위험 방어 보험료 검토 및 완화 조치 실행"
            action_blueprint["article_id"] = "Risk_Mitigation_Plan"
        else:
            action_blueprint["status"] = "Low"
            action_blueprint["action"] = "정상 운영 유지 및 데이터 모니터링"
            action_blueprint["article_id"] = "Compliance_Check"

        return action_blueprint

## 🚀 MVP 핵심 기능 정의 (The Core 3)

MVP의 목표는 **"사용자가 리스크를 인지하고, 시스템을 통해 통제권을 회복하며, 구체적인 다음 행동을 취하게 만드는 것"**을 최소한의 기능으로 증명하는 것입니다.

| 순위 | 핵심 기능 (Feature) | 목표 가치 (Value Proposition) | 포함 범위 (MVP Scope) |
| :--- | :--- | :--- | :--- |
| **1순위** | **리스크 점수 산출 및 법적 근거 제시 모듈** | 위험의 객관적 측정 및 신뢰성 확보 (Risk Insurance의 기반) | 기본 리스크 변수 입력 $\rightarrow$ 정량화된 리스크 점수 출력 $\rightarrow$ 해당 점수에 연동되는 최소한의 법적 근거(Article ID) 표시. |
| **2순위** | **권한 확보 경로 시각화 및 액션 플랜 제시 모듈** | 통제권 회복 (Authority Flow) 및 명확한 다음 행동 지침 제공 | 리스크 점수 변화에 따른 '불안 $\rightarrow$ 통제' 감정 아크 시각화 $\rightarrow$ 리스크 해결을 위한 3단계 Actionable Blueprint(다음 행동 단계) 제시. |
| **3순위** | **핵심 KPI 대시보드 (단일 위험 집중)** | 사용자가 관리해야 할 핵심 지표를 단순화하여 제공 | 현재 가장 높은 위험 요인 및 그에 따른 권고 사항을 실시간으로 표시하는 '위험 현황판(Risk Dashboard)'. |

### 🎯 불필요한 기능 제외 근거:
*   **제외된 기능:** 복잡한 데이터 통합, 다중 법규 자동 분석 엔진, 광범위한 시장 경쟁사 ROI 심층 비교 등은 MVP 출시 후 **'확장 단계(Phase 2)'**에서 추가하여 사용자 피드백을 반영하며 고도화할 예정입니다.
*   **집중 이유:** MVP는 '핵심 가설(리스크 관리 $\rightarrow$ 통제권 회복)'이 작동하는지 검증하는 데 집중해야 하며, 복잡한 분석 기능은 사용자가 충분히 신뢰를 쌓은 후 추가되어야 합니다.

### 📊 초기 핵심 성과 지표 (MVP KPIs)
MVP의 성공은 기능의 복잡성이 아닌, 제공된 가치에 대한 사용자의 반응을 측정하는 데 있습니다.

1.  **행동 전환율 (Action Conversion Rate):** 리스크 점수 확인 후 '다음 행동(Blueprint)' 버튼 클릭 비율. *(목표: 30% 이상)*
2.  **세션 유지율 (Session Retention):** 위험 현황판에 접속한 사용자가 다음 세션에서 재방문하는 비율. *(목표: 주간 1회 이상 방문)*
3.  **인식된 통제감 지수 (Perceived Control Index - PCI):** 사용자 만족도 설문(Micro-survey)을 통해 리스크 상황 인지 전후의 심리적 안정감 변화를 측정. *(목표: 평균 +20점 이상 획득)*

### 1. 백엔드: RiskService 클래스 및 테스트 케이스 구현

리스크 계산의 핵심인 법적 근거와 가중치를 반영하여 `RiskService`를 설계하고, 요구된 세 가지 시나리오에 대한 테스트를 수행합니다.

<create_file path="src/services/RiskService.ts">
class RiskService {
    // 리스크 가중치 설정 (예시 값이며, 실제 법규 및 비즈니스 목표에 따라 조정되어야 함)
    private static WEIGHTS = {
        legalRisk: 0.5,       // 법적 근거 관련 위험 점수 가중치
        marketVolatility: 0.3, // 시장 변동성 관련 위험 점수 가중치
        complexity: 0.2,      // 시스템 복잡성 및 관리 난이도 관련 위험 점수 가중치
    };

    // 법적 근거와 벌금 액수를 기반으로 리스크를 계산하는 핵심 로직
    public calculateRiskScore(articleId: string, penaltyAmount: number, marketIndex: number): { score: number, riskLevel: 'Normal' | 'Warning' | 'Critical', actionPlan: string } {
        // 1. 법적 위험 점수 산출 (Article ID 기반)
        let legalRiskScore = 0;
        if (articleId.startsWith('CR')) { // 예시: CR(Criminal/Compliance) 관련 조항이 포함된 경우 고위험
            legalRiskScore = 50;
        } else if (articleId.startsWith('REG')) { // 일반 규제 관련
            legalRiskScore = 20;
        } else {
            legalRiskScore = 10;
        }

        // 2. 시장 변동성 위험 점수 산출
        let marketRiskScore = Math.abs(marketIndex - 100) * 1.5; // 기준점 100에서 벗어날수록 가중치 증가

        // 3. 복잡성 위험 점수 산출 (시스템 구조의 복잡도에 따라)
        let complexityRiskScore = 10 + Math.floor(Math.random() * 20); // 실제로는 시스템 설계 복잡도를 반영해야 함

        // 최종 리스크 점수 계산 (가중치 적용)
        let totalRiskScore = (legalRiskScore * this.WEIGHTS.legalRisk) + 
                             (marketRiskScore * this.WEIGHTS.marketVolatility) + 
                             (complexityRiskScore * this.WEIGHTS.complexity);

        // 리스크 레벨 결정
        let riskLevel: 'Normal' | 'Warning' | 'Critical';
        let actionPlan: string;

        if (totalRiskScore < 30) {
            riskLevel = 'Normal';
            actionPlan = "현재 안정적입니다. 권한 확보 경로(Authority Flow)를 점진적으로 강화하세요.";
        } else if (totalRiskScore < 65) {
            riskLevel = 'Warning';
            actionPlan = "경고 단계입니다. 법적 근거 조항과 시장 변동성을 재검토하고 통제권 확보 계획을 즉시 실행하세요.";
        } else {
            riskLevel = 'Critical';
            actionPlan = "위험 임계값을 초과했습니다. 즉각적인 행동이 필요하며, 시스템 안정성 확보를 위한 긴급 조치(Hard Stop)를 검토하십시오.";
        }

        return { score: Math.round(totalRiskScore), riskLevel, actionPlan };
    }

    // 테스트 케이스 실행 함수
    public runTestScenarios(): void {
        console.log("--- RiskService Test Scenarios ---");
        const testCases = [
            { id: "Normal", articleId: "REG-001", penaltyAmount: 1000, marketIndex: 105 }, // 낮은 위험
            { id: "Warning", articleId: "CR-202", penaltyAmount: 5000, marketIndex: 90 },  // 중간 위험 (경고)
            { id: "Critical", articleId: "CR-999", penaltyAmount: 10000, marketIndex: 120 } // 높은 위험 (위험)
        ];

        testCases.forEach(test => {
            const result = this.calculateRiskScore(test.articleId, test.penaltyAmount, test.marketIndex);
            console.log(`\nScenario: ${test.id} (${test.articleId})`);
            console.log(`  결과: Score=${result.score}, Level=${result.riskLevel}`);
            console.log(`  Action Plan: ${result.actionPlan}`);
        });
    }
}

import React from 'react';

interface RiskData {
    score: number;
    riskLevel: 'Normal' | 'Warning' | 'Critical';
    actionPlan: string;
}

interface RiskDashboardCardProps {
    riskData: RiskData;
}

const RiskDashboardCard: React.FC<RiskDashboardCardProps> = ({ riskData }) => {
    let colorClass = '';
    switch (riskData.riskLevel) {
        case 'Normal':
            colorClass = 'bg-green-100 border-green-500 text-green-800';
            break;
        case 'Warning':
            colorClass = 'bg-yellow-100 border-yellow-500 text-yellow-800';
            break;
        case 'Critical':
            colorClass = 'bg-red-100 border-red-500 text-red-800';
            break;
    }

    return (
        <div className={`p-6 rounded-lg shadow-md border-l-4 ${colorClass}`}>
            <h3 className="text-xl font-bold mb-2">리스크 상태: {riskData.riskLevel}</h3>
            <p className="text-3xl font-extrabold mb-4 text-gray-900">{riskData.score}</p>
            <div className="mt-4 p-3 border-t border-gray-300">
                <h4 className="font-semibold mb-1">다음 행동 지침 (Actionable Blueprint)</h4>
                <p className="text-sm text-gray-700">{riskData.actionPlan}</p>
            </div>
        </div>
    );
};

export default RiskDashboardCard;

기존 $199는 단순한 '컴플라이언스 준수' 서비스를 넘어선 **'위험 통제권 회복(Risk Control Recovery)'**이라는 고차원적인 경험을 판매합니다. 이 가격은 기능의 비용이 아닌, 고객이 겪는 **불안감 해소와 잠재적 손실 방어**라는 심리적 가치에 기반해야 합니다.

| 요소 | 기존 $199의 근거 | 전략적 해석 |
| :--- | :--- | :--- |
| **가치 제안** | 법적 준수 + 리스크 점수 시각화 | 단순 정보 제공이 아닌, '불안(Pain) $\rightarrow$ 통제(Control)'의 감정적 여정을 경험하게 함. |
| **ROI 관점** | 잠재적 벌금 및 운영 위험 회피 비용 절감 | 고객이 지불하는 금액보다 훨씬 큰 잠재적 손실 방어 가치를 제공함. |
| **시장 포지셔닝** | B2B 규제 준수 툴 (Compliance Tool) | 일반적인 솔루션 대비, 법적 리스크에 대한 '선제적 보험'으로 포지셔닝됨. |

**결론:** $199는 MVP 출시 시점에서는 합리적이며, **프리미엄 서비스의 시작점(Entry Point)**으로서 충분히 정당성을 가집니다. 다만, 확장성 확보를 위해 티어링 전략을 통해 더 높은 가치를 제공해야 합니다.

### 3. 경쟁사 대비 차별화된 3단계 가격 플랜 (Tiered Pricing Model)

가격 구조는 **'정보 제공(Compliance)'**에서 시작하여 **'위험 통제(Risk Control)'**를 거쳐 **'전략적 권한 확보(Authority Flow)'**로 심화되는 감정적 아크에 맞춰 설계합니다.

#### 🥇 Tier 1: Foundation (기반) - $49/월 (Freemium/Entry Point)
*   **목표:** 잠재 고객의 진입 장벽 제거 및 데이터 확보. (Lead Generation & Basic Compliance)
*   **포함 기능:** 기본 리스크 점수 산출(Base Score), 법적 근거 요약, 월간 리포트 조회 제한.
*   **가치 제안:** **"기본적인 위험 인지 및 최소한의 규제 준수 정보 제공."** (불안감 시작 단계)

#### 🥈 Tier 2: Authority (권위 확보) - $199/월 (Core Offering)
*   **목표:** 핵심 가치(Authority Flow) 경험 판매 및 전환 유도. (Control & Actionable Blueprint)
*   **포함 기능:** Tier 1 전체 + **'Actionable Blueprint' 자동 생성**, 리스크 점수 변화에 따른 맞춤형 법적 대응 시나리오, 경쟁사 비교 분석 기능 활성화.
*   **가치 제안:** **"불안을 통제하고 즉각적인 행동 계획(Authority Flow)을 확보하는 실질적인 도구."** (핵심 경험 제공)

#### 🥉 Tier 3: Command (지휘) - $499+/월 (Premium/Enterprise)
*   **목표:** 고위험군 및 대규모 팀 대상의 완전한 통제권 확보. (Full Control & Proactive Strategy)
*   **포함 기능:** Tier 2 전체 + **실시간 데이터 스트리밍 연동(API), AI 기반 선제적 위험 예측 모델**, 법률 자문 통합 모듈, 전담 컨설턴트 연계 옵션.
*   **가치 제안:** **"잠재적 손실을 완전히 제거하고 시장을 선도하는 전략적 통제권 확보."** (최고 수준의 안전성 및 전략 제공)

## 💡 최종 와이어프레임 상세 기획안: Critical Risk $\rightarrow$ Relief Flow

이 기획안은 사용자가 **Critical(위험) 상태**를 인지한 후, 시스템이 제시하는 **Actionable Blueprint(해결책)**을 통해 즉각적인 **통제권 회복(Relief)**을 경험하도록 디자인됩니다. 핵심은 **Red $\rightarrow$ Gold/Green 전환의 역동성**에 있습니다.

### 1. 핵심 목표: 감정 아크 관리 (Emotional Arc Management)

| 단계 | 사용자 상태 | 시각적 목표 | 주된 색상 변화 | 마이크로 인터랙션 목표 |
| :--- | :--- | :--- | :--- | :--- |
| **Phase 1: 인지** | 높은 불안감 (Anxiety) | 위험의 심각성 즉각 인지 | **Red** 강조 (경고/긴급) | 경고 메시지의 순간적 진동(Pulse) 또는 깜박임. |
| **Phase 2: 전환** | 해결책 탐색 (Search for Solution) | 통제권 확보 경로 제시 | Red $\rightarrow$ Amber (주의) | Actionable Blueprint가 로딩되는 동안, 경고 표시를 부드럽게 희석시키며 다음 단계로 시선 유도. |
| **Phase 3: 안도** | 해결책 수용 (Relief/Control Restored) | 통제권 회복 및 실행 가능성 확보 | Amber $\rightarrow$ Deep Forest Green + Rich Gold | Blueprint가 완전히 제시되는 순간, 배경 색상을 안정적인 녹색 계열로 전환하고 핵심 경로에 **Rich Gold** 하이라이트. |

### 2. Critical 레벨 상세 인터랙션 시퀀스 (Micro-interaction Sequence)

**상황:** 사용자가 리스크 점수(Score)가 **Critical** 상태임을 인지한 직후, `Actionable Blueprint` 섹션이 활성화되는 순간.

#### A. 초기 상태 (Risk = Critical)
*   **배경/카드 색상:** 강렬한 **Red** 또는 **Deep Red**.
*   **텍스트 강조:** `Critical` 레벨의 텍스트는 가장 크고 진하게 표시되며, 시스템 지표 설명(`시스템 통제권 확보율: XX%`)은 **Rich Gold**로 대비되어 표시됨.
*   **인터랙션:** 카드 전체에 미세한 **Red Pulse (100ms)** 애니메이션을 적용하여 긴급성을 유지.

#### B. 해결책 제시 시점 (Actionable Blueprint Load)
1.  **Transition Effect:** `Actionable Blueprint` 섹션이 나타나기 시작할 때, 현재의 Red 상태는 즉시 사라지지 않고 **Amber**로 부드럽게 페이드(Fade) 전환됩니다. (Red $\rightarrow$ Amber Transition).
2.  **Focus Shift:** 사용자의 시선은 자동으로 새로 등장하는 `Actionable Blueprint` 목록으로 이동하며, 이 과정에서 카드 중앙의 Red 강조는 점차 약해집니다.
3.  **Blueprint Highlighting:** 제시되는 각 단계(`Step 1`, `Step 2`)는 **Deep Forest Green** 배경 위에 **Rich Gold** 테두리 또는 아이콘으로 명확하게 강조됩니다. 이는 '실행 가능한 경로'임을 시각적으로 확증합니다.

#### C. 최종 상태 (Relief Achieved)
*   **최종 색상:** 카드 전체 배경이 안정적인 **Deep Forest Green**으로 전환됩니다.
*   **핵심 요소:** `Actionable Blueprint` 내의 각 단계는 **Rich Gold**로 명확하게 표시되어, 사용자가 이제 '통제권 확보'라는 목표를 향해 나아갈 수 있음을 확인합니다.

## 💡 최종 UI/UX 가이드라인 확정 보고서: 리스크 전환 애니메이션 검토

개발팀이 구현한 'Critical'에서 'Relief'로의 상태 전환 로직에 대해, 감정적 아크(Emotional Arc) 극대화 관점에서 최종 사용자 검토 결과를 바탕으로 디자인 시스템 가이드라인을 확정합니다.

### 1. 핵심 목표: 감정적 흐름의 시각화 (Anxiety $\rightarrow$ Control/Relief)

**목표:** 사용자가 리스크를 인지하는 순간(불안/긴장)에서, 시스템이 통제권(Control)을 확보하고 안도감(Relief)으로 전환되는 과정을 **즉각적이고 명확하게** 시각화하여 심리적 안정감을 제공합니다.

### 2. 애니메이션 및 색상 변화 로직 확정 (Micro-interaction Specification)

| 상태 전환 | 시작 색상 (Anxiety/Risk) | 목표 색상 (Control/Relief) | 전환 방식 (Animation Type) | 타이밍 및 속도 (Timing & Duration) | 감정적 효과 |
| :---: | :---: | :---: | :---: | :---: | :---: |
| **Critical $\rightarrow$ Amber** | Red (`#FF0000`) | Amber (`#FFC107`) | Smooth Fade (Soft Transition) | 300ms | 경고 및 주의 집중 |
| **Amber $\rightarrow$ Deep Forest Green** | Amber (`#FFC107`) | Deep Forest Green (`#1E4D2B`) | Rapid Pulse/Wipe (Dynamic Shift) | 200ms | 조치 필요성 인지 및 행동 유도 |
| **Deep Forest Green $\rightarrow$ Gold** | Deep Forest Green (`#1E4D2B`) | Rich Gold (`#FFD700`) | Slow, Subtle Fade In (Subtle Reveal) | 500ms | 통제권 확보 및 안정감 부여 |

### 3. 디자인 시스템 적용 상세 지침

#### A. 색상 사용 원칙 (Color Hierarchy for Emotional Arc)
1. **위험 경고 (Red):** 'Critical' 상태에서 잠시 표시되어 즉각적인 주의를 환기합니다. 이는 일시적이고 긴급한 느낌을 줍니다.

*   **최대 효과 구간:** `Amber`에서 `Deep Forest Green`으로 전환하는 200ms 구간에 가장 높은 시각적 대비와 역동적인 변화를 적용하여, 사용자가 **'위험을 인지하고 즉시 통제권을 확보한다'**는 감정적 흐름이 극대화되도록 설계합니다.
